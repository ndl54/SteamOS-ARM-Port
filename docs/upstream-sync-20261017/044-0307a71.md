## Data producer and refresh trace

The old Recent gate was `sessions.length > 0 && fps is absent/null`. Gamescope's `paint_all` in `external-and-mods/gamescope/src/steamcompmgr.cpp` emits an FPS sample every 300 frames, including Steam redraws, and separately emits a focus line. The dashboard's `FpsReader` consumes only FPS lines and expires a reading after three seconds. Therefore FPS freshness is not a reliable indication that a game is focused. The upstream change correctly removes that dependency.

Gamescope publishes `GAMESCOPE_FOCUSED_APP` using the input-focus window's app ID when a focus window exists; it publishes an empty property for zero in Steam mode. Dashboard `Games.poll()` runs xprop on the Steam process's DISPLAY (same-user /proc discovery, fallback `:0`) and maps IDs 0 and 769 to no game. `Games.watch()` polls on a three-second loop and updates its locked app ID. `Games.state()` returns this integer, a manifest-derived name (possibly empty), remembered settings and artwork. This is focus identity, not a process-liveness signal: a running game can lose focus.

`/state` returns `GAMES.state(cfg)`, `FPS.get()` and `sessions_get(4)`. `Main.qml` polls state once per second on dashboard/skins, on entering dashboard, after relevant POSTs, more gently on home, and through the existing 15-second light-state timer off dashboard. `/nav` is separately polled every 400 ms. Accepted non-hidden responses replace `Ui.st`; initial state is `{}`. Failed HTTP/JSON requests reach the callback as null and hidden responses are ignored, retaining the previous snapshot. No freshness timestamp or request-order guard is introduced here.

The dashboard Recent card is the local session log, distinct from Home's `/recent` launchable games list and its 30-second cache/polling. `DashPage.pushStats()` observes app-ID transitions and posts the preceding session to `/session` if its observed duration is at least one minute. Session storage normalizes numeric fields, caps names at 80 characters, retains 200 entries and replaces a temporary JSON file atomically. Reads return the last four entries newest first with resolved cover paths; absent/unreadable/invalid JSON returns an empty list. These producer/storage paths are unchanged.

## Findings and resolution

The upstream condition uses `game.name` as its game-presence test. `Games.name()` only searches app manifests and caches even an empty result. A focused non-Steam game or unavailable manifest can therefore have a nonzero app ID and no name. Reproduced the source predicate returning true for that focused game, which exposes Recent during gameplay despite the stated between-games policy.

Use `rows.length > 0 && !(dash.st.game && dash.st.game.appid)` instead. The backend already normalizes Steam/no-focus IDs to zero. Missing or null game data remains tolerated; a nonzero ID hides Recent even if paused, FPS is stale, or metadata is unavailable. No display-name lookup, backend polling, session logging or game controls are changed. The existing GAME controls still require a name; their separate presentation behavior is outside this correction.

The original FPS-toggle failure is reproduced against the assigned source's parent; the missing-name gap is reproduced against the assigned source itself. Before the local app-ID correction, the eight-test harness had five passes and three failures: missing-name identity, a deliberately synthetic stale label at ID zero, and switching to an unnamed focused game. After correction all eight pass.

## Remaining risks and evidence boundary

Focus detection still depends on the correct Steam display, xprop/property availability, and asynchronous polling. A failed xprop maps to zero; a caught watch exception retains old focus. The three-second watch plus state polling can delay visibility changes, and real focus transitions/overlays can still toggle it. Desktop Mode may have no Gamescope focus property. Failed/hidden HTTP responses retain stale state indefinitely, and overlapping successful replies can arrive out of order. These inherited limitations were inspected, not expanded into a backend redesign.

Session capture depends on UI observation and may miss time while the UI/process is absent. Syntactically valid but malformed session JSON is not comprehensively schema-validated; concurrent session writes, missing artwork, changing row counts, repaint behavior and actual touch/layout performance remain unverified. The name cache and name-gated GAME controls retain their existing limitations.
