## USB-C routing

The new helper replaces the pinned package helper only in the Baldur staged rootfs. Its source behavior serializes on flock, discovers the TLMM gpiochip dynamically, gives a local source/host candidate priority, retries host reconciliation after usb_role changes, and probes both sink ports for gadget enumeration with bounded waits. The new71 rule supplements the pinned70 Type-C partner rule; boot-only recovery remains separate. GPIO30 selects bottom/side HS routing; DP lanes and USB-C audio are not implemented by this helper.

The upstream comments called these partner roles. [Linux Type-C ABI](https://www.kernel.org/doc/Documentation/ABI/testing/sysfs-class-typec) specifies that port power_role/data_role describe the **local port**. Corrected that description without reversing the intended local-host predicate. A PC while the tablet sinks is not a source/host candidate; sink device/gadget paths handle it. Actual firmware misreporting claims remain upstream observations, not evidence collected here.

Repairs:

- Exact NUL-separated `lenovo,baldur` gate before opening a lock or reading/writing hardware state; direct invocation on Elden/EVO/lookalike names is a no-op.
- Preserve the currently routed host connector when still eligible, avoiding bottom-priority disconnection of an existing side controller when a second host candidate appears.
- Refuse mux/role changes while any USB interface has usb-storage or uas bound. This intentionally errs toward preserving storage regardless of mount namespace, raw/swap/holder use or which connector it belongs to. Device-path guards recheck before successive mutations.
- Fail on lock-open failure, failed/invalid GPIO read, failed GPIO write, unknown side power role and source/device inconsistency. Do not fall into a device path after failure to read an existing host route. Single-port and boot-recovery role writes propagate errors.
- Recheck host eligibility around routing; retain configured/suspended gadget guards, bounded dual-port probing, host no-op reconciliation and separate boot recovery.

This is not transactional switching. Kernel UCSI and physical unplug/role changes do not take this shell lock; checks can race with the next write. The storage guard may refuse otherwise usable transitions and cannot stop the kernel itself from changing role. There is no claim of dock/PC/controller compatibility, sustained GPIO ownership after gpioset exits, guaranteed USB storage protection, hotplug latency or actual udev timing. Existing direct RUN helpers may wait behind the lock; no host udev/systemd service was started.

**Resolution:** retain the existing conservative boot attenuation159 on both `on` and `off`; do not import the new unqualified high-gain policy. Keep the filter chain and its LADSPA prerequisites, bounded card/sink retries, default-to-filter selection and both-channel fail-safe writes. The pinned boot mixer helper still has its existing configuration behavior; arbitrary user changes elsewhere are outside this guarantee.159 is the pinned conservative baseline, not a new acoustic certification.

Add exact Baldur gating, restrict discovery to the TB323FU card identity instead of any LENOVO card, establish conservative attenuation before querying PipeWire, and bound pactl calls with timeout. Keep an explicitly chosen Bluetooth/headphone default. Use ExecStopPost so conservative restoration is also attempted after failed startup, as documented by [systemd service lifecycle](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html). Status now propagates mixer read failures. No mixer/channel success is claimed if either write fails; restoration failure is reported.

Physical speaker excursion/temperature, ALSA driver gain units, UCM/firmware, LADSPA ABI/filter routing and real stop/start timing remain unverified. The conservative policy may be quieter.
