## Review and resolution

Reviewed the complete one-file source diff, its masking loop and surrounding overlay installation, the equivalent masks in `scripts/apply-overlays.sh`, the SM8750 image builder's overlay invocation and filesystem copying, the common initramfs's early `/etc` mount, the home-expansion service/helper, tablet conversion and home.mount replacement, and the SM8750 overlay paths for later overrides.

The source masks `steamos-boot.service`, `efi.mount`, `esp.mount` and `systemd-repart.service` on SM8750. The upstream rationale is that Deck EFI dependencies wait for absent partitions and repart can consume space intended for the existing home partition. Those observed delays/partition changes are upstream claims, not device observations from this review. The image builder creates boot/root/home partitions and calls this overlay installer before copying the rootfs. Elden userdata conversion subsequently copies that rootfs, replaces home.mount with the self-bind unit, and stamps home expansion as complete.

Systemd documents that a unit symlinked to `/dev/null` cannot be activated; `/etc/systemd/system` precedes the ordinary vendor unit directory. See the [systemd v257 unit documentation](https://github.com/systemd/systemd/blob/v257/man/systemd.unit.xml). Masking is therefore necessary even when a vendor target still has a wants link. This documentation check does not establish the shipped rootfs's exact systemd version or complete dependency graph.

### Fixed: an upper unit could hide the new lower mask

The source writes the four masks only to base `/etc`. The common initramfs mounts `/var/lib/overlays/etc/upper` over `/etc` before starting systemd, and the SM8750 image builder preserves that directory when copying the rootfs. A regular unit or vendor symlink already in upper therefore hides the lower mask. This is the same layering concern identified for home.mount in review 005.

Moved the four Deck units into a dedicated small loop over base `/etc` and an existing upper directory. It creates systemd directories as needed, removes their multi-user/default system wants links, and replaces each unit with a `/dev/null` symlink. It does not create an otherwise absent overlay upper. Mask-write failures remain fatal under the script's `set -e`; existing VR cleanup remains unchanged. Deck entries are system units, so the new block does not remove names from the user manager's wants directory as the original shared loop did.

No home.mount, home-expansion helper/stamp, fstab, common initramfs, kernel or existing fork-specific behavior changed. The only product diff from starting main is this 14-line block in the SM8750-specific overlay installer. Thus the BusyBox explicit-loop fallback, built-in loop/OverlayFS requests, tablet self-bind home in both layers, safe cleanup, FAST/cache validation, CSOT selection and staging/installer fixes from earlier integrations are preserved byte-for-byte. EVO's separate shared-overlay path, kernel recipe/patches, bootdebug, UFS-bound policy, Wi-Fi, audio, LEDs and Gamescope remain untouched.
