### Fixed: cleanup could delete a mounted output filesystem

The new upstream EXIT cleanup disabled error handling, attempted each unmount, then unconditionally detached loops and recursively deleted the temporary directory. If an output mount was busy, that deletion could descend into its still-mounted FAT/ext4 filesystem and destroy generated contents.

Cleanup now tracks unmount failures, skips loop detachment and recursive deletion when any unmount fails, retains the directory when detachment fails, and reports recovery paths. It preserves an existing failing exit status and explicitly exits nonzero when cleanup itself fails after otherwise successful work. Explicit exit is necessary because merely returning a failure from an EXIT trap does not replace the original successful exit status.

Added a focused regression test that mocks every mount, unmount, loop-detach and deletion operation. It exercises each of the five busy mount positions, both loop-detach failures, successful cleanup, and original error-status preservation. The same lightweight test file verifies the command-line parser and applies the real sed/awk transformations to menu text derived from the current staging template. No image or staging script is executed by the tests.
