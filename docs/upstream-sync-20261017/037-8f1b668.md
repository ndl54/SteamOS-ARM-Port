## Change and event flow

The only product change is the assigned six-line diff in `sm8650-overlay/usr/lib/konkr/konkr-volume`. Inside `Volume.apply()`, writing `Speakers Volume=17,17` now requires `force=True`. Ordinary changed-volume events continue to write both `WSA_RX0 Digital Volume` and `WSA_RX1 Digital Volume`; unchanged target events do not repeat those writes. The existing curve, mute/zero handling, maximum clamp, two-channel software-volume policy and Steam/PulseAudio bar values are unchanged.

The separate `sm8550-volume-keys` service watches its allowed GPIO/PMIC/InputPlumber keyboard devices and invokes `apply(code)` only for EV_KEY value 1. Up unmutes the default sink and adds the configured percentage step, capped at the configured limit; down subtracts the step; mute toggles. Release and value-2 autorepeat events are ignored at this revision. Repeated physical presses therefore produce separate PulseAudio updates; this source does not implement hold-to-repeat. Steam/UI volume changes reach the same daemon through PulseAudio notifications.

`konkr-volume` subscribes to sink, server and card events, calling ordinary `apply()` for each. It controls the named internal Speaker sink, not whatever output is currently the default. Thus the key helper may change headphones/DP/Bluetooth while this daemon continues to observe the internal speaker's own value. No new route switching, PCM selection, codec enable/disable or digital gain value is introduced.

A mock sequence of startup plus five changed volume positions previously wrote the PA six times. After integration it writes the PA once, while retaining all twelve digital-channel writes. Duplicate events do not add writes. This proves removal of the redundant command in the inspected execution path; the source's audible-dropout claim has not been verified on hardware here.

## Activation, asynchronous recovery and failure limits

- Staging installs the shared overlay helper and enables its user unit through the vendor `default.target.wants` directory. The unit runs after PipeWire/PulseAudio/WirePlumber, excludes root, and executes the helper's `--check-board` condition. The direct `main()` entry repeats the same board check.
- The retained guard compares the complete DT model, after stripping trailing NUL bytes, to `KONKR Pocket FIT`. It excludes FIT Elite, Pocket S2, Pocket EVO, tablets, case differences and suffix near-matches. Sharing APS2 card naming with S2 does not activate this daemon there.
- Startup still calls `apply(force=True)`. Missing bar or sink returns before mixer writes. A later event or polling pass can discover the sink; a drifted PA then triggers the forced path.
- The periodic thread sleeps three seconds, clears the cached node under the lock, reapplies volume and checks PA readback. Stable `values=17,17` produces no PA write. Drift or a failed/empty read triggers `apply(force=True)`, which writes the PA and both digital controls. A failed PA write that leaves drift visible is retried on subsequent passes. The interval includes command execution and lock waiting; it is not a strict three-second recovery deadline.
- `apply()` and `forget_node()` retain their mutex. The node ID remains a local copy during application, so the polling thread cannot turn an in-flight command argument into `None`. Subscription and polling still share serialized application; the PA readback occurs outside that lock, as before. Redundant force after a concurrent state change remains possible.
- Software-volume drift is checked every application, independently of the cached digital target. Node replacement is rediscovered by polling. Subscription EOF waits one second and reconnects; process-start exceptions are not caught locally and rely on the unit's existing `Restart=always`, `RestartSec=2` policy.
- Each `run()` invocation retains its three-second timeout and catches timeout/OS errors. It returns stdout only and does not validate exit status or stderr. Consequently a failed digital write may still update `last`, preventing an identical target from retrying until a target change or forced application. Only PA drift is read back periodically. A digital-only reset with stable PA and unchanged target is likewise not detected. These are inherited limitations, not fixes claimed by this source.
- Hard-coded ALSA card `0`, the fixed speaker node name, mixer control names, first-channel software-volume inspection and the cached digital maximum/fallback remain assumptions for later image/device validation. No gain table or acoustic-safety conclusion was derived from mocks.
