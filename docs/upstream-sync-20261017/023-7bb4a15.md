## Wi-Fi integration and repairs

The source removes unbound Qualcomm (`0x17cb`) PCI network-class (`0x0280*`) devices when Wi-Fi is absent, rescans PCI, waits and falls back to reloading ath12k modules. Retained that ordering with these narrow repairs:

1. Match exact NUL-separated `lenovo,elden` in the wrapper as well as the existing exact systemd firmware condition. Direct invocation on EVO, TB321FU or an Elden near-match returns before extraction or hardware actions.
2. Detect a registered wireless interface by its `phy80211` entry, independent of interface name. An existing `wlp1s0` now suppresses disruptive recovery just as `wlan0` would. Presence does not mean association, DHCP, connectivity or usable radio firmware.
3. Only request the global PCI rescan after at least one matching unbound device was successfully removed. Do not remove bound devices, other vendors or non-network devices. Report remove/rescan write failures and retain module fallback and the nonblocking Bluetooth request.
4. Poll up to 30 half-second sleeps after a successful rescan, then fall back to `modprobe -r ath12k_wifi7 ath12k` followed by `ath12k_wifi7` or `ath12k`. Poll again after that attempt so asynchronous interface creation can be observed. The explicit polling budget is at most 30 seconds total, not a deadline for kernel/module operations. Use a shell arithmetic loop rather than external seq.
5. Keep `systemctl --no-block try-restart bluetooth.service`; waiting synchronously would conflict with the unit's Before=bluetooth ordering. Keep extraction failure propagation, temporary marker cleanup and existing offline-remoteproc recovery. Log interface presence rather than claiming Wi-Fi connectivity or guaranteed hardware power cycling.

## Installation, persistence, ordering and retry boundaries

`apply-overlays-sm8750.sh` installs these helpers and the unit when an extra kernel output ends in `-elden-steamos`. The later SM8750 overlay contains no replacement copy of these three files. The normal EVO image path does not enable this Elden installation. Elden's recipe alone selects `/var/lib/steamos-arm/firmware/elden` through `firmware_class.path`; TB321FU retains its separate `/usr/lib/firmware/steamos-arm/tb321fu` and EVO does not acquire either tablet override.

In the tablet converter/common initramfs path, userdata supplies the writable root, including /var; the extractor's destination survives normal boots. It searches existing private files, then exact digests in shared `/usr/lib/firmware` and Android trees; name fallback still uses only Android trees. Correct copies can supply every alias. Shared base firmware is not rewritten by this runtime step. A later shared-firmware staging copy cannot overwrite the private /var destination. Existing private fallback bytes are checked/replaced against discoverable Android candidates, but the code does not prune unrelated stale files. Built-in firmware, cached firmware and user cmdline overrides remain outside this filesystem-copy guarantee.

The unit is ordered after local-fs and udev-settle, and before NetworkManager, Bluetooth and display-manager, with a five-minute start timeout. Ordering does not prevent an earlier kernel probe or require successful firmware extraction before those services operate. An existing /etc unit/mask/drop-in, including one in the persistent /etc upper mounted before systemd, can override the /usr unit. This source does not overwrite user service overrides. The installer's existing base/upper KWin calibration merge and all tablet mount/mask handling remain untouched.

Recovery is a best-effort **changed-files boot action**, not a continuous retry service. Missing files with no new writes do not trigger it; a completed but unsuccessful Wi-Fi attempt returns success after logging and requesting Bluetooth asynchronously. An explicit restart with unchanged files also skips recovery. On a later boot the normal driver probe gets the persisted files; a future extraction that changes bytes triggers recovery again. No recovery-pending stamp or automatic restart policy was added. An interruption after copying but before writing the marker can similarly leave no immediate same-boot retry. The PCI scan remains global once a target has been removed, and any already-present wireless interface suppresses recovery; multiple-radio configurations are unvalidated.
