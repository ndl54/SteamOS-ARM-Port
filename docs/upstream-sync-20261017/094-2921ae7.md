The source adds an executable shell predicate, stages it in both overlay recipes and changes eligible partition events from ID_FS_USAGE=filesystem to old-system. It does not contain Steam's formatting implementation, a partition plan or a consent dialog. The intended result is to prevent the old SD root/home from becoming game mounts, leaving the user to choose formatting in Steam.

The predicate only concatenates filesystem labels from a glob. The claim that the card is no longer used by the system is not established by the predicate. `mmcblk*` also includes eMMC, labels can be copied, and flattening label output loses per-partition identity. ## Resolution and delivered scope

Kept the source's two staging additions and old-system property, replacing the predicate with a self-contained read-only Python3 implementation. Existing runtime Python3 use is already present in the storage helpers; no new package installation occurs here. The executable mode0755 is retained.

Eligibility now requires:

- An exact `mmcblkNp1`, p2 or p3 event, canonical sysfs nodes matching `/dev` block major:minor, physical whole-card ancestry, device/type=SD, a 32-hex CID and a positive disk sequence. eMMC, UFS/USB targets, arbitrary aliases, malformed names and missing identity refuse.
- Exactly three kernel partitions p1/p2/p3 on that card, distinct device identities, correct partition numbers, positive ordered non-overlapping geometry inside capacity, writable nodes, no whole-device slaves and no holders on the card or its partitions.
- Direct `/` ext4, `/boot` vfat and `/home` ext4 mounts, each at filesystem root, with canonical major:minor mappings onto partitions of the **same Qualcomm UFS disk**. Driver ancestry must resolve to ufshcd-qcom. SD boot, mixed SD boot/home, USB/eMMC/loop/dm/overlay root, subdirectory roots, duplicate or missing required mounts refuse. No classification is inferred from UFS filesystem labels.
- No card or partition major:minor in the current mount namespace, including aliases and bind mounts. No active block or file swap on the card. No loop backed by its block devices or filesystems. Unreadable/unknown loop or swap backing evidence refuses; an active loop lacking backing evidence is not assumed idle. Unconfigured zero-size loops are allowed.
- Three explicit read-only `blkid -p` probes, each with a two-second subprocess timeout: p1 BOOT/vfat, p2 root/ext4, p3 home/ext4. Cached results, glob ordering and whitespace-substring matching are not used. Probe failure, unavailable tool, ambiguous/duplicate output keys and mismatched layout refuse.
- A second complete identity/activity snapshot after probing must match the first, including CID, disk sequence, canonical node paths/inodes, device numbers, geometry and mount rows. This detects observed removal/replacement and intervening mounts; it is not an atomic lock against future changes.

The udev rule still requires filesystem usage, and now additionally requires UDISKS_IGNORE not equal to1. Thus an earlier protected/system classification is not overwritten, and the helper never clears UDISKS_IGNORE. Existing system-disk detection and internal-UFS exclusion lines are byte-preserved. The upstream `old-system` property is an automount hint only, not a trusted obsolete-data marker or grant to erase the disk.

The [systemd udev manual](https://www.freedesktop.org/software/systemd/man/latest/udev.html) confirms lexical rule ordering, the all-match requirement, PROGRAM success matching and inequality for absent properties. This is documentation evidence only, not execution of the packaged udev version. No udevadm test/trigger, service start or live rule reload was run.

## Important functionality and destructive-action boundaries

**This is a deliberately narrower feature than the source claim.** Coldplug before `/boot` and `/home` are mounted refuses classification. No late retry/retrigger service is introduced. A card inserted after the verified internal layout is mounted can match; a card already present during early boot may still take the inherited automount path. A card already mounted anywhere is refused and is never forcibly unmounted. The coldplug/Steam end-to-end problem therefore remains unresolved pending final image/runtime review.

Refusal means this new rule does not assign old-system. It does **not** mean all preexisting automount or formatter behavior is now certified safe; the original properties/rules continue. The legacy is-system-disk helper retains its direct-source limitations. User rules or later rules may also change the property. The actual base-image 99-steamos-automount.rules and Steam formatter are not vendored here, so source review cannot establish that the packaged Steam client offers the desired card or handles old-system as expected.

No format/partition plan or write action is added. No GPT, filesystem, mount, backup, boot slot or card contents are changed by this helper. It does not open or delete backup files. In particular, the SD may still contain the only original ABL/GPT/boot backup, games or saves: matching the layout is not proof that these are redundant or copied successfully. The explicit destructive consent and target/preflight revalidation belong to the actual formatter at invocation time. This integration neither grants passwordless writes nor bypasses081's administrator authentication.

A formatter's write failure cannot be rolled back by this hint. Repartitioning/formatting is destructive; table backup alone does not restore erased data. Steam's partition plan, current-device binding, concurrent hotplug handling, failure recovery and consent UX require review of the actual shipped implementation before claiming end-to-end safety. There is no automatic rollback, repair, resize, unmount or retry here.
