## Independent review and repairs

Reviewed the source diff, helper event/audio paths, service lifecycle and installation references in `scripts/apply-overlays.sh`, `scripts/apply-overlays-sm8750.sh`, and `gamescope-onready`. Read EVO InputPlumber device/capability maps, the existing evdev state-query example in `gen5-emergency-key`, and report 088. No installer or preparation entrypoint was executed.

The upstream implementation adds an immediate step, a 0.4-second hold delay and 0.1-second repeat interval, tracking the most recently pressed volume key by `(fd, key)`. It ignores hardware autorepeat value 2 and clears the held key on its matching release or an OSError/path removal. The intended feature and defaults are retained, with the following fixes:

1. **Missing releases and input lifetime.** Empty reads previously left the held key live. EOF and read errors now remove its fd/state; transient `BlockingIOError` does not remove a live fd. Each timed step checks `EVIOCGKEY` and cancels on a released key or ioctl failure. `SYN_DROPPED` cancels repeat and ignores events through `SYN_REPORT`, requiring a new press. This deliberately favors stopping over reconstructing an uncertain hold.
2. **Repeat cadence and duplicate events.** Duplicate value-1 presses no longer cause extra steps or reset the delay; value 2 remains ignored, including mute. Read ready input before firing the timer. Schedule each repeat from the completion of the preceding audio command, so a slow command cannot collapse the interval into immediate back-to-back commands. Latest direction wins; release of another key/device does not cancel it, and releasing the active key does not resurrect an older held key. Mute stays one-shot.
3. **Suspend and cleanup.** Compare Linux `CLOCK_BOOTTIME` with `CLOCK_MONOTONIC`; a suspend gap over 0.1 seconds closes/reopens input handles, discards queued old events and cancels repeat. A fresh press is required after resume. Normal exceptions unwind through fd cleanup; process termination also relies on OS fd cleanup. There are no timer threads, detached repeat workers or cross-thread shared state. The existing 10-second hotplug scan remains.
4. **Invalid repeat configuration.** Nonfinite, invalid, negative, zero and sub-50-ms timing values fall back to the original defaults instead of crashing or producing a tight repeat loop.
5. **Audio query and target safety.** Resolve the default sink once per action and use that concrete sink name throughout the action. A default-route switch between query and write therefore does not apply one sink's percentage to a different default sink. Upward adjustment retains the existing PulseAudio percentage scale and configured upper bound (default 100%); empty/malformed queries and invalid step/limit values fail closed instead of fabricating zero or raising. Set volume before unmuting. Downward adjustment preserves the existing relative per-channel decrement and server zero-floor behavior, avoiding a new stereo-balance reset. Mute uses the resolved sink once. Subsequent repeat actions intentionally re-resolve the then-current default sink.

Only the volume helper is changed in product code. The additional files are the focused fake-I/O regression and this report. Device discovery allowlist, lack of exclusive input grab, service user/root restriction, executable staging, EVO input mappings, exact-board guards, UCM/gain paths and sleep behavior remain unchanged. Every tracked product file outside the helper is byte-identical to the starting HEAD, preserving 083–088 including the UFS inherited-patch skip deduplication and legacy skips.

## Remaining risks and evidence boundary

These are source and fake-I/O results only. No build scripts, source-preparation entrypoints, make/compiler, kernel/Gamescope/InputPlumber/rootfs/image/package compilation, installation, flash, deployment or real-device tests were run. No real host volume was changed. Full queue completion remains prerequisite to build validation.

Real evdev/ioctl behavior, Linux suspend timing, input hotplug, InputPlumber event routing and actual PipeWire/pactl integration remain unverified. The unchanged allowlist assumes raw grabbed events and virtual keyboard events are not delivered twice; two distinct fds producing the same physical press are not globally deduplicated. The single active-direction policy is intentional. Suspend intervals at or below the 0.1-second detection threshold are not canceled by that check, although current-key verification still runs before repeats.

Audio commands remain synchronous with individual two-second timeouts, so cancellation cannot retract a command already submitted and UI responsiveness depends on the audio server. There is no cross-process lock or atomic read/modify/write with Steam or other volume writers. Upward adjustment retains the pre-existing first-channel percentage policy; asymmetric channel balance on volume-up is not redesigned. Downward lower saturation remains the audio server's responsibility. Missing sink names or failed queries skip an upward step; device removal or route changes between separate commands can still cause a skipped/failed command. Existing process ownership/service behavior is preserved; this does not enforce a machine-wide singleton across independent user managers.

The prior 075 critical GPU trips, 076 haptics lifetime/concurrency and 078 Elite gain findings remain for final global review and are not altered by this item.
