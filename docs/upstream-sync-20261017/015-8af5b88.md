With default shader rotation, the session requests full composition, making the composition buffer format relevant to Game Mode output.

Only an exact NUL-delimited `lenovo,elden` compatible enables `GAMESCOPE_PREFER_8BIT=1` by default. A nonempty inherited value is respected, including `0`. Neither bare `qcom,sm8750`, Odin 3, TB321FU nor Pocket EVO activates that default. Modifiers remain enabled according to existing capability detection unless explicitly disabled; upstream did **not** make linear buffers the Elden default.

The two explicit cmdline controls apply to any board:

| Input | Result |
| --- | --- |
| `steamos.gamescope.8bit=0` / `=1` | Override the inherited/default preference with that exact value |
| `steamos.gamescope.modifiers=0` | Export `GAMESCOPE_DISABLE_MODIFIERS=1` |
| `steamos.gamescope.modifiers=1` | Unset that variable, restoring normal capability-based handling |
| Invalid/empty values | Ignore them and retain the preceding inherited/default/valid setting |
| Repeated valid keys | Last valid occurrence wins |

Direct environment variables retain Gamescope's existing `env_to_bool` numeric/atoi semantics. The strict `0|1` validation applies to these new cmdline controls, not all Gamescope variables.

`init_drm` gathers KMS plane formats and `pick_plane_format` also checks Vulkan sampled/storage/transfer-source features. The new preference tries XRGB8888/ARGB8888 for the primary composition buffer, and ARGB8888 for partial composition where overlay planes exist. Unsupported 8-bit formats fall back to the previous 10-bit RGB, 10-bit BGR, then 8-bit RGB sequence. Without overlay planes, the existing alpha-format derivation follows the selected primary format. `GetPreferredOutputFormat` passes the choices to `vulkan_make_output`; `vulkan_make_output_images` allocates the composition images. This is a **preference for composition buffers**, not an unconditional ban on 10-bit client direct scanout, a guarantee of panel/link bit depth, or a new HDR capability.

## Repairs made during integration

1. **Exact board gate.** Replaced the source's substring grep with NUL-to-newline conversion and exact whole-line matching. The original wrongly enabled the default for `lenovo,elden-other` and other strings containing the name. The existing exact EVO gate remains untouched.

2. **Invalid cmdline values no longer defeat the board default.** The source accepted every `8bit=*` value; for example `8bit=bad` replaced Elden's `1`, and `atoi("bad")` disabled the preference. Accept only the documented `0` and `1`, matching the already-strict modifiers override.

3. **Actually request linear composition buffers when disabling modifiers.** The source only cleared `drm->allow_modifiers`. That changes `UsesModifiers()` and the DRM AddFB path, but `CVulkanTexture::BInit` otherwise defaults to `VK_IMAGE_TILING_OPTIMAL`; it does not establish a linear layout. Added a default-false `RequiresLinearScanout()` backend policy, enabled only by the DRM backend's explicit environment setting. Vulkan now sets `bLinear` for newly allocated flippable images and skips explicit modifier allocation under this policy. Format eligibility uses `linearTilingFeatures`, so a format supported only with optimal/compressed layouts cannot be selected as a supposedly linear candidate.

   The deferred backend forwards this initialization-independent policy to its child. Its existing `UsesModifiers()` always returns true, so merely setting `bLinear` without also skipping the modifier allocation branch would still export an explicit LINEAR modifier that the disabled DRM importer rejects. The new branch covers that path too. Nested/VR/headless backends inherit false and retain their existing allocation behavior. Imported client DMA-BUF layouts are not relabeled or converted by this allocation change. Existing DRM rejection of explicit modifiers and fallback composition remain; implicit client buffers are not newly validated as linear. The guarantee here is the requested layout of Gamescope's own scanout allocations, subject to successful Vulkan/KMS creation.

4. **Truthful format log.** The source logged successful 8 bpc selection even when `pick_plane_format` returned INVALID. Log the chosen 8-bit composition path only on success, otherwise state that default formats will be tried. The modifier log likewise describes implicit KMS imports and linear compositor buffers, rather than claiming every possible client scanout is linear.
