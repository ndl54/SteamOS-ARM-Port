### Root action, command handling and shutdown

Decky's existing plugin.json requests root. Handheld RPC additionally requires effective uid0 and uses fixed argv with no shell, caller-provided command/path, sudo or pkexec. It sends `systemctl --no-block --no-ask-password reboot --reboot-argument=bootloader`, outside the async event loop, with a ten-second client timeout. Nonzero status, missing binary, permission failure and timeout return false. No force/instant reboot and no fallback to another restart command.

[Systemd258 documentation](https://www.freedesktop.org/software/systemd/man/258/systemctl.html) describes passing the reboot argument to the reboot system call and nonblocking job submission. That supports the interface interpretation, not the target image's command version, kernel restart handler or actual ABL behavior. Success means request acceptance only. A timeout can occur after submission, so failure is not proof that reboot was cancelled.

Handhelds do not access boot/ABL partitions, alter GPT/active slots or write UEFI boot mode. Therefore no new storage backup/readback or partition lock belongs to this path. Normal systemd shutdown owns sync/service ordering; no sleep preparation, MCU, RTC, poweroff or recovery hook is invoked directly. Requests are not serialized against unrelated power actions or other systemctl clients; final boot-mode selection remains in firmware. Real shutdown ordering and concurrent job behavior are unverified.

### Preserve both distinct tablet storage operations

Kept helper-based capability checks with an eight-second check timeout, async execution and missing-helper/error handling. Did not restore upstream's `findmnt | grep mmcblk` heuristic, which cannot distinguish SD from eMMC. Mutation still invokes the same independently validating helpers; no timeout was added around a storage-writing helper that could kill it mid-write.

- Elden: exact board, writable direct ext4 SD root/CID/major:minor, unique boot_a/boot_b on the same separate Qualcomm UFS disk, matching GPT/sysfs identities/geometry, valid boot magic and unambiguous active B. Mount/swap/holder/loop and firmware-use exclusions remain. Its root-only mutation holds the shared tablet-gpt lock, preserves table/sector backups, revalidates, changes both entries in one sfdisk transaction, checks complete table readback, syncs, then requests nonblocking reboot. A becomes active; B loses active. No blind rollback after failure.
- Baldur: exact board and inherited SD/UFS checks, equal boot sizes, active A and matching recorded full boot_b Android hash. Under the shared lock it saves/verifies boot_a, revalidates, copies B to A, flushes/verifies A and only then requests reboot. It never changes GPT slot bits. This differs fundamentally from Elden; the source's generic slot-A description was not retained.

These helper files and the033/068 ABL backup/flash/restore protections are byte-identical to starting main. Partial-write recovery, external writers, power loss, advisory-lock limits, foreign backups, signature/AVB acceptance and actual Android boot remain the prior reports' unresolved boundaries. A reboot-command failure can leave tablet boot storage changed; the UI keeps that warning.
