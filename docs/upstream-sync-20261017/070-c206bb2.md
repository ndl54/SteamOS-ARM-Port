The log's reported battery percentage is still a best-effort first Battery reading, not a validated battery estimator.

A hold still starts SteamOS; short press shows charge briefly. On unplug, request `systemctl --no-block poweroff` with a timeout; an accepted request keeps the start job blocked until shutdown stops it, while a failed request logs failure and releases with a nonzero status/restored brightness. This avoids waiting synchronously for a shutdown transaction that must stop the starting service itself.

Checked [systemd service command/ordering documentation](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) and [inhibitor interface](https://www.freedesktop.org/software/systemd/man/latest/systemd-inhibit.html). Invalid active split can fall back to a valid later candidate. Existing known-digest matches still have higher priority than name fallback.

Revalidate during publication, write through `.part`/replace, preserve unchanged output and raise the existing changed marker only on writes. Failure is missing/partial firmware rather than a successful covered path. Log the selected header accurately (ordinary bundles retain header-last ordering). Closed the manifest read explicitly after a new fixture exposed its old ResourceWarning.

Structural validation is not firmware authentication, release compatibility or a complete transactional bundle update. Existing LP/Virtual-A-B/cleanup limitations from010 remain. The256MiB limit is a conservative resource bound, not a device specification; oversized legitimate images are refused. Hash preference can still select an older known image; ambiguous/missing filenames remain missing. The unchanged boot wrapper decides recovery from its existing header/marker policy, not from new proof that a GPU/DSP actually loaded.
