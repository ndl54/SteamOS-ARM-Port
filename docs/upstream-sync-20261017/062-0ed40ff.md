## Actual launch and update policy

Both common and SM8750 overlay scripts install RUNSTEAM to `/usr/share/deckard` and the image's Steam home. The common installer also documents the stock steam.service copy-on-start path; the stock base unit/select_steam implementation is not tracked here, so its exact behavior has not been independently verified against a running image. The selected ARM runtime is steamrtarm64, falling back to linuxarm64 if the former is absent. Steam stays a native ARM launch, with handheld gamepad/SteamDeck flags; no VR/Frame startup flag is added.

The marker in the resolved Steam root **or** exact inherited `STEAM_ALLOW_CLIENT_UPDATES=1` enables updates. A value of 0/empty/other text does not cancel an existing marker. The Gamescope environment file only transfers its existing explicit refresh/Mangoapp variables; an arbitrary terminal environment does not automatically reach steam.service. Existing service `STEAM_EXTRA_ARGS` includes the two suppression flags. With opt-in, RUNSTEAM strips every exact `-inhibitbootstrap` and `-nobootstrapperupdate` token, including service/extra duplicates. Other flags, including `-noverifyfiles`, remain. Without opt-in the defaults remain. Sideload argv from devkit JSON remains explicitly authoritative and is not filtered. Existing extra-argument word splitting/globbing and sideload JSON parsing are not redesigned.

The source unconditionally deletes root and selected-runtime steam.cfg on opt-in, and overwrites the root file otherwise. This loses unrelated user configuration. The repair edits both locations atomically per file, removes only the five exact shipped default lines, adds missing defaults when updates are disabled, and preserves all other bytes/keys and mode. Existing non-default bootstrap values remain user-owned (including inhibition values that can prevent an opted-in update). A symlink/nonregular file or write failure is reported and aborts launcher startup instead of silently launching with a stale policy. Unchanged files are not rewritten. Missing runtime directories are skipped and retain the existing later launch failure behavior.

Legacy installer/RUNSTEAM did not mark ownership of the five lines: an identical manually authored value is indistinguishable and is migrated too. Custom values/formatting can continue to inhibit updates. These boundaries are documented in tips.md. Opt-out blocks future updates under the shipped policy and never downloads or restores an older Steam version. The separate image seeding installer still resets its image seed; it is not run on each RUNSTEAM invocation and was not changed here.

The existing exec of the Steam command remains; no shell supervisor/retry loop was added. The service retains Restart=on-failure plus RestartForceExitStatus=42 for Steam-requested restarts, including client changes, and BindsTo/PartOf gamescope-session. OOBE uses systemctl restart with its existing SIGKILL fallback. Those files are unchanged. Python configuration failures are nonzero and could therefore trigger service retries until repaired. Actual client update/download/restart behavior remains untested. Quoted the final `cd` so it does not independently split a Steam root containing spaces; pre-existing FEX command-path expansions elsewhere remain unquoted and are not certified for unusual full-launch paths.

## Remote Play routing, fixes and lifecycle

The marker requests a wrapper at the selected native runtime's `streaming_client`; its target is `steamrt64/streaming_client` under explicit box64, not FEX or a game compatibility tool. The feature neither changes host discovery nor selects a remote computer/codec/session. The source's ARM-vs-x86 PyroWave decoder and SDL3_ttf callback/SIGILL rationale are upstream claims, not device observations obtained here. A compatible beta client, its x86 libraries and host codec support remain prerequisites; the marker does not fetch any of them.

Repairs to the source wrapper setup:

1. Validate executable regular ELF64 little-endian headers and machine183 for native backup, machine62 for the x86 target. The source only checked three magic letters for native and executable permission for x86. Header validation is structural, not a loader/ABI/signature check.
2. Copy the native client to an atomic same-directory backup **before** publishing a wrapper. A failed backup/chmod/write/rename leaves the native client intact. The source ignored failed mv and then truncated the active binary. A new native client supplied by an update refreshes the backup on the next launcher start.
3. Publish/restore through unique same-directory temporary files. Preserve executable modes; remove owned temporary files on handled failure. Refuse symlink/nonregular destinations. Replace only a genuine native ELF or the shebang/marker-owned wrapper; opt-out does not overwrite an unrelated script. Retain the .arm64 recovery copy after restoration.
4. Serialize cooperating setup invocations with a per-root flock, released when the short Python helper exits. Steam's updater and manual editors do not take this lock; it is not a global transaction or power-loss guarantee.
5. Derive the Steam root physically from the wrapper location instead of embedding a single-quoted path. This handles spaces/apostrophes and the `~/.steam/binarm64` directory symlink. The original generated script is syntactically invalid for an apostrophe-containing root.
6. Discover box64 in PATH with `/usr/local/bin/box64` fallback. The existing builder stages that binary and a `/usr/bin/box64` symlink; steam.service's restricted PATH omits `/usr/local/bin`. No box64 build/install was run.
7. Create the resolved Steam root's logs directory before redirection (also correct for sideloads). Immediately before exec, a removed opt-in, absent box64 or missing executable x86 target routes to the saved native client. A started box64 process's exit code is propagated, without automatically starting a second stream after failure. A missing/corrupt backup is reported; no native binary is invented.

The wrapper prepends the required emulated SDL3_ttf library and its Steam x86 search directories while retaining inherited BOX64_EMULATED_LIBS/BOX64_LD_LIBRARY_PATH entries. The official [box64 usage documentation](https://raw.githubusercontent.com/ptitSeb/box64/main/docs/USAGE.md) confirms the colon-delimited forced-library list and x86 library search variable; this current reference is not proof of the target's installed box64 version. Native LD_LIBRARY_PATH, Vulkan/display/audio and other inherited settings remain; LD_PRELOAD is cleared on the x86 route to avoid carrying a native/overlay preload into it. Explicit BOX64_LD_PRELOAD and other box64 options remain unchanged. Existing RUNSTEAM FEX-based runtime-library discovery and game FEX/FrameGen settings are byte-preserved.

All routes use exec, preserving arguments and process status without an extra background child or global pkill. No new process-cleanup service is required by the wrapper itself. Real Steam child reaping, service cgroup cleanup, focus/window identity, audio/input, SDL/Vulkan callback ABI and remote-stream teardown still need runtime validation. The inherited stock gamescope-cleanup implementation/base service was not present for inspection; no claim of complete live process cleanup is made. An unusable log path yields a visible failed launch rather than discarding output silently. A setup failure is reported while Steam startup continues, so Remote Play can remain unavailable if an already-damaged wrapper has no valid backup.
