## Decoder review: metadata, layout, ownership and errors

The four identical patches remove the `TIER_AV1` generic setter and replace hardcoded POC zero with `inst->fw_caps[POC].value`. These are Iris HFI gen2 stream-property changes, not pixel-plane conversion code.

Read-only external source references used for the independent review:

- [Linux stable v7.2.8 Iris sources](https://github.com/gregkh/linux/tree/v7.2.8/drivers/media/platform/qcom/iris): capability table, command/config dispatch, response/source-change handlers, controls, packet construction, decoder stream-on and vb2 locking/last-buffer paths.
- [Linux v7.2 Iris sources](https://github.com/torvalds/linux/tree/v7.2/drivers/media/platform/qcom/iris): corresponding SM8750 base files.
- [Pinned Elden kernel 5134673b3b0492578d44c6b229477aa697b17f17](https://github.com/h0cheung/tb322fc-linux-kernel/tree/5134673b3b0492578d44c6b229477aa697b17f17/drivers/media/platform/qcom/iris): capability table, commands, response, controls, packet construction and decoder paths. This is the recipe's exact source pin.

The source-change response records the firmware POC in `src_subcr_params.pic_order_cnt`, then `fw_caps[POC].value`. POC's default capability value is1, with range0–2. The old command always sent0 and overwrote the subscription cache with0. Reusing the per-instance capability preserves the reported value on restart (and uses the existing default before a report). The command remains `HFI_PROP_PIC_ORDER_CNT_TYPE`, `HFI_PAYLOAD_U32`, exactly `sizeof(u32)`, with the existing plane-to-port conversion.

`iris_set_properties()` first calls codec-specific configuration, then iterates all valid capabilities with non-null setters. The dedicated `iris_hfi_gen2_set_tier()` already selects `TIER_AV1` for AV1 and `TIER` otherwise and sends the bitstream-port tier. The subsequent generic TIER_AV1 setter was not codec-gated and sent its default0 to the same input port, overwriting HEVC's selected tier. Removing just that setter retains the capability and dedicated AV1 dispatch; the loop explicitly checks for a null setter. The separate TIER setter and encoder capability table are unchanged.

The new POC local variable is still a stack u32 copied synchronously by the existing packet constructor's `memcpy` into the instance packet before queue submission; no pointer to that local is newly retained. There is no new allocation, mapping, buffer owner, queue/requeue, DMA-BUF import/export, file descriptor, plane pitch/offset/size, NV12/P010/UBWC layout, colorimetry, crop, fence or release operation. Source-change and vb2 stream-on use the existing instance mutex. Packet/queue error returns and configuration-loop propagation remain intact. Existing generic capability-setter return values are ignored by the baseline loop; this patch removes one such call and does not repair or claim full error-path correctness.

The baseline response stores reported tier in TIER, whereas the AV1 command chooses TIER_AV1. This pre-existing AV1 tier-cache distinction is unchanged; no claim of complete AV1 High-tier handling follows from the HEVC fix. Firmware-input validation and all other metadata/layout negotiation remain baseline behavior. The subject's universal green-screen claim is not accepted as a measured result: repeated decoding, restart/drain, colors and actual frame output require runtime evidence.
