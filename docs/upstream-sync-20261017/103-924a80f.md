## Assigned behavior and limits

Both state-path branches now use `gamescope/backlight-top-nits-2`: XDG_STATE_HOME first, otherwise HOME/.local/state, otherwise no persistence. This ignores the old unversioned file; it neither deletes that file nor migrates its value. Loading is lazy, once per process, on the first value above 1. Missing/unreadable/invalid/nonfinite/top-at-most-1 state leaves the top at zero. A finite parsed numeric prefix is sufficient; this is not a strict whole-file format. Writes still create the directory and directly truncate the file, silently tolerating failures.

With no learned top, the first finite value above 1 is accepted. With an existing top, a larger input replaces it only if it is at most 1.5 times that top. A larger jump leaves the top unchanged and normally clamps normalized output to full brightness. Example: top 500, stray 2000, then 500 preserves top 500 and full output; previously the last 500 mapped to about 24.8%. Exactly 750 is accepted from 500; the next representable float above 750 is rejected. The comparison is inclusive and uses float arithmetic.

This addresses only part of070's recorded risk. It is **not calibrated panel-maximum detection**:

- First-sample poisoning remains: first 2000 then 500 still leaves the latter below 25%.
- Moderate outliers and successive accepted increases can still raise the top indefinitely: 500 -> 750 -> 1125 all pass.
- A legitimate large jump is also rejected. First 100 then 500 leaves top 100, flattening the upper slider range until sufficiently small intermediate increases arrive. Merely repeating 500 does not relearn it. The new state filename makes first-sample behavior relevant again after upgrade.
- Top never decreases; no connector, SDR/HDR, panel, session or explicit calibration reset event clears it in-process. Deleting state while the process runs does not reset the once-loaded value.
- State is shared per user, not keyed by panel/connector/Steam range. Multiple sessions can race truncating writes, and a crash can leave a partial file. No cross-process lock or atomic/power-loss-safe persistence is added.
- The first finite value and loaded finite top have no physical upper bound. FLT_MAX is rejected against a normal top, but a huge initial/loaded top remains possible; multiplying such a top by 1.5 can overflow to infinity. No claim of universal outlier rejection is made.

Retain this source's deliberate growth heuristic rather than inventing a panel calibration or repetition-based promotion rule without an authoritative endpoint signal. These limitations require final brightness-policy review/device evidence; the commit subject must not be read as a complete cure for070.

## Units, consumers and bounded repair

The actual input path is steamcompmgr's `GAMESCOPE_INTERNAL_DISPLAY_BRIGHTNESS` CARDINAL bit-cast float -> ApplySteamBrightnessValue -> SteamValueToNormalized -> SetBacklightNormalized. Values at most 1 use normalized clamping (including negative -> zero); values above 1 are nits, with no percent branch. The default minimum is 5 nits, clamped to zero through half of learned top; normalization divides by max(1, top - minimum) and clamps to [0,1]. Exact 1 therefore takes the normalized branch. `backlight_max_nits` remains compatibility-only and unused. Corrected the stale public-header percent comment and the claim that learning always tracks the highest observed value.

**Repair: reject nonfinite Steam input before reporting acceptance.** Previously SteamValueToNormalized returned s_flLastNorm for NaN/Inf, then SetBacklightNormalized returned true. The unchanged atom handler used that true result to send the original nonfinite input to `set_internal_display_brightness`; its lower-bound/equality checks do not reject NaN or positive infinity. Therefore holding the physical level did not protect the color-management path. ApplySteamBrightnessValue now returns false before normalization for NaN and either infinity, so the handler skips the entire gain/color update. Removed the now-unneeded unlocked last-level read from the private normalizer.

SetBacklightNormalized also rejects a nonfinite normalized result before changing last-level state, clamping, lround or sysfs. This covers direct API misuse and NaN produced by a malformed `backlight_min_nits` convar (the generic numeric parser has no finite-value filter). The repair does not replace or reset user convars. A finite nits input can still update the top before a NaN minimum causes its eventual normalized output to be refused. No change to finite normalization, learned-top threshold, physical brightness floor, software curve, HDR metadata policy or hardware failure behavior.

The current direct normalizer caller is exclusively ApplySteamBrightnessValue. The only tracked Apply caller is the compositor atom handler. InitBacklight runs before starting the compositor thread; brightness keys in wlserver call StepBacklight. Get/Set/hardware-state access uses the existing mutex. Top/load/save remains owned by the compositor caller and is not a new generally thread-safe API. The Step read-then-write pair is not atomic relative to Steam updates, and external sysfs writers are not serialized by this mutex. No concurrency guarantee beyond this source trace is claimed.
