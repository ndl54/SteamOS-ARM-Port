## Findings and resolutions

1. **Retry only a missing-blob mismatch.** Replaced substring matching with `DeltaMismatch`, exit9 and a structured target fingerprint. The updater emits this only after normal failed-stage cleanup completes. Signature, board, checksum, space, boot, unmount and generic errors remain nonretryable. Malformed protocol output also fails closed. One full retry only; no loop.
2. **Bind selection to the signed release and target.** The agent passes expected version on every stage, requires full content for a full candidate, and supplies the delta's target fingerprint on fallback. The updater checks these after signature/model/architecture validation and before mounting/planning. The fingerprint covers format, architecture, version, sorted device list and entire inventory (paths, contents, metadata, links and whiteouts); it intentionally excludes kind/from/blob transport fields. A renamed wrong-version package, another same-version target or another board set cannot substitute silently. Full candidates must declare kind=full and list every regular-file target hash. Automatic updates require signed format2; standalone format1 CLI/GUI usage retains its previous checksum requirement.
3. **Preserve download ownership.** Replaced the shared deterministic package path with a private per-invocation TemporaryDirectory. Reject a symlink cache or a cache owned by another effective user/group-world writable. Remove only the invocation's own copied/downloaded file; never truncate/delete earlier downloads, media originals or other cache entries. Cleanup occurs before success is published. No secrets or `.env` changes.
4. **Space and failure propagation.** Check download space against advertised/local size plus 256 MiB before copying either candidate. In format2, check HOME for required extracted blobs, existing regular-file backups and a 512 MiB recovery/boot reserve before extraction/backup. Retain the existing system-partition check and payload hashes. A full transfer/copy/checksum/stage exception or nonzero stage result yields an error; no done/100% result follows it.
5. **Do not recursively delete through a failed unmount.** Previously stage2's failed unmount could reach stage's `rmtree(work)` with rootview still bound to the live root. Failed-stage cleanup now conservatively retains work whenever rootview remains or a pending marker exists, and raises a nonretryable error. A clean missing-blob rejection removes only its unmounted, uncommitted transaction. Existing cleanup's mount/pending safeguards remain unchanged.
6. **Do not treat a partial boot stage as success on the next invocation.** A format2 transaction records `staging-incomplete` before publishing pending, removing it only after boot staging finishes. Status exposes `stage_failed` and withholds `staged` while the marker remains. The agent reports failure and asks for recovery instead of returning already-staged code8. Steam's unchanged duplicate predicate therefore cannot turn that condition into an already-staged success. Pending recovery data stays intact; recovery state names and rollback behavior are unchanged.

The agent and updater now share additional CLI flags/protocol and must be shipped together. Existing image staging installs both; an inconsistent new-agent/old-updater installation fails closed on unsupported arguments rather than silently relaxing validation.

## Remaining risks and boundary

**No build/compile/package compilation, compiler syntax-only, bundling, kernel/Gamescope/InputPlumber/rootfs/image build, VM/container/session/service start, mount, real device/sysfs access, update download/application, install, flash, deploy or reboot. No hardware testing.** Python parsing and mocked function execution are local control-flow evidence only. Signature operations were mocked; tar extraction, real bind mounts, ownership/xattrs, kernel retargeting, recovery and power-loss behavior need later Linux/image/device validation.

Space checks are estimates with reserves, not reservations; concurrent writes, unknown advertised size, unusually large recovery runtime, inode exhaustion and boot-partition capacity can still fail. Such operation failures must surface as errors; this review does not establish sufficient storage on any device. Abrupt termination may leave private downloads until manual cleanup, or a pending incomplete transaction requiring recovery. Conservative retention of rootview can also leave an empty failed work directory; existing cleanup can later remove it once no mount/pending state exists.

The installed inventory's existing size/mtime shortcut remains; this is not a new full rehash of every unchanged file. Signed-package schema/tar processing and symlink/power-loss behavior have not received a comprehensive security audit. The unchanged generic managed-tree policy and upstream package source do not promise preservation of arbitrary live custom profiles or fork binaries. Prior EVO/SM8250/Desktop/Mesa hardware and build risks remain open. Final build validation stays with the separately authorized post-109 stage.
