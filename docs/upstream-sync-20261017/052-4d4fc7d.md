## Findings and resolutions

1. **Rollback must restore the installed inventory.** `backup_plan` now explicitly includes the generated inventory even though it is absent from the package target; `restore2` includes it in restoration/removal. HOME backup-space estimation includes its size. A failed apply or rollback request restores the previous inventory bytes/version/hash cache. If the original image had no inventory, rollback removes the newly generated one. For an older transaction with no inventory backup, this updater conservatively removes the untrusted inventory instead of claiming the failed release is installed; it cannot infer the previous version.
2. **Pending is not installed.** The display helper reads only installed.json, never candidate/transaction versions, and declines to change labels while the pending marker exists, including an incomplete/failed stage or interrupted recovery. The upstream helper could label a new inventory while the transaction was still unresolved. Successful commit removes pending and exposes the new release; rollback restores the previous inventory and its label. No new pending/error UI or status protocol was introduced.
3. **Preserve OS identity and custom configuration.** Only PRETTY_NAME is changed. Unlike the assigned source, VERSION stays Frame's, alongside VERSION_ID, BUILD_ID, NAME, ID, VARIANT_ID and unrelated custom keys/comments. This avoids combining an ARM project version in VERSION with a different underlying Frame VERSION_ID. Existing file ownership/mode are retained. Duplicate PRETTY_NAME entries are normalized, other text is retained, and unchanged files are not rewritten.
4. **Contain offline symlinks and atomic publication.** Image symlinks, including absolute `/usr/lib/os-release` and parent symlinks, resolve within the supplied root instead of reading host identity files. Resolution is bounded against loops. `/etc/os-release` can become its own file without writing through its final symlink. Runtime only targets `/etc`, with a guard against a parent link redirecting the write elsewhere; `/usr` remains untouched at runtime. Unique same-directory temporary files replace the fixed `.tmp` name, and failed publication removes only that temporary file. Missing/invalid/non-object inventories, non-string versions and non-ASCII/non-numeric version strings do not produce a label.
5. **Record final image hashes.** Both overlay scripts now label the offline root with their explicit STEAMOS_ARM_VERSION (same existing default), then record inventory. The upstream order recorded stale pre-label hashes. The helper's explicit version option is restricted to offline roots. It also updates an existing offline `/var/lib/overlays/etc/upper/os-release`, so that layer cannot hide the image's label at first boot. Runtime reads the active `/etc` overlay after recovery/local-fs.
