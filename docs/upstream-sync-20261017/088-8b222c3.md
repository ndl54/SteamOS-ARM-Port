## Independent semantic review

Reviewed the actual pinned `drivers/ufs/core/ufshcd.c` and `include/ufs/ufs.h`, before and after patches, including completion, command submission, retries, buffer cleanup, descriptor setup, timestamp calls, initial probe, PM resume and host recovery.

- **Unsupported IDN versus transport failure:** `QUERY_RESULT_INVALID_IDN` is 0xFD. Only that Query Response status gains the `-EOPNOTSUPP` mapping. Successful responses still copy query data; other response statuses remain `-EINVAL`, rejected UPIUs remain `-EPERM`. `ufshcd_exec_dev_cmd` invokes the response decoder only after `ufshcd_issue_dev_cmd` succeeds, so transport/OCS failures are not remapped by this change. Opcode/IDN remain observable through `dev_dbg`.
- **Retries and propagation:** flag and attribute retry wrappers immediately return `-EOPNOTSUPP`; descriptor retry adds it to existing terminal conditions. Other error/retry behavior is unchanged, including descriptor's pre-existing terminal `-EINVAL`. Suppressing redundant error logs does not turn an unsupported required descriptor/flag into success: the error still propagates and callers retain their own failure handling. Qword requests are single attempts already.
- **Cleanup/data:** unsupported branches jump to existing cleanup, release device-management/clock locks, clear the descriptor pointer, and free temporary buffers where appropriate. They bypass consumption of a failed response, and preserve output-buffer behavior on error. No SCSI read/write data command, partition logic, filesystem, block-device layout, or storage encryption path is changed.
- **Timestamp gating:** `timestamp_sup` is initialized only after generic and vendor device-quirk fixups, using the existing UFS version >= 0x400 and absence of `UFS_DEVICE_QUIRK_NO_TIMESTAMP_SUPPORT`. Old-version and known-quirk devices continue to skip the write. A confirmed `-EOPNOTSUPP` clears the capability; other errors, including `-ETIMEDOUT` and `-EIO`, remain logged and do not clear it. Timestamp encoding and the real-time clock value are unchanged.
- **PM/recovery/lifetime:** initial device-parameter discovery precedes timestamp use. Normal resume retains the capability and writes only after the device becomes active. Host-reset recovery calls device initialization/probe with `init_dev_params=false`, retaining the remembered rejection. A new full parameter discovery/driver lifetime can reinitialize capability and try again; this is not persistent storage across boots. Existing link recovery, power transitions, device-management synchronization, and separate UFS RTC update worker are unchanged. No new work item, IRQ path or allocation lifetime is introduced.
