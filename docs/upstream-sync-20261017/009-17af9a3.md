## Integration repairs

### Retry other candidates and keep polling after mount failure

The source selects only the first FAT/exFAT HOTPLUG row and breaks even if its mount fails. A bad first partition prevents use of a valid second one and cancels the advertised waiting period. Iterate every candidate, break out only after successful mounting, and otherwise continue the bounded polling loop. Preserve the source's FAT/exFAT and HOTPLUG filters.

### Restrict the fallback to USB ancestry

HOTPLUG alone also selects removable non-USB media. Reuse the common initramfs's existing `/sys/class/block/...` resolved-path USB ancestry check before mounting. This avoids treating an SD card or internal UFS sd* name as a USB stick. No board-name substring matching or generic EVO gate was introduced.

### Release only the collector's USB mount

The source leaves its new mount active indefinitely after capture. Track successful mount ownership and install exit/HUP/INT/TERM cleanup to sync and unmount that USB path after the whole collector finishes, or when it exits early. The mount is retained through the existing approximately three-minute snapshots plus thirty-minute performance capture; the early DONE.txt on non-EVO still describes boot snapshots, not completion of performance capture. A failed unmount is reported and the mount directory is left intact. There is no lazy/forced unmount, recursive deletion, loop detach or block-device mutation.

Skip an already-mounted USB target to avoid stacking on or taking ownership of another mount; failed creation of the mount directory falls back to the root destination. A failed log-directory creation also runs owned-mount cleanup. Make its error message name the actual destination instead of always claiming /boot failed.

This is normal single-service ownership, not a new interprocess locking mechanism. Concurrent manual invocations, SIGKILL, power loss, disappearing media, kernel I/O stalls and desktop automount interaction are not solved by shell traps. A busy unmount can still leave the mount active, with a diagnostic.
