## Repairs made during integration

1. **GPT slot parsing:** source loses bit 50 when it is the final token in newline-terminated sfdisk output, including `GUID:50\n`. Split on whitespace/commas, accept only `_a`/`_b` cmdline values and ignore failed sfdisk reads. The read command passes no attribute value, so it cannot set GPT attributes. [util-linux v2.41.1 sfdisk.c](https://github.com/util-linux/util-linux/blob/v2.41.1/disk-utils/sfdisk.c), `command_partattrs`, confirms read-only opening and newline output. The existing boot-success writer is unchanged and was not executed.

2. **Logical metadata slot and tree priority:** source reads slot-0 LP metadata even after detecting active B. Select primary metadata at `12288 + slot * metadata_max_size`, matching [AOSP Android 15 liblp](https://github.com/aosp-mirror/platform_system_core/blob/android-15.0.0_r1/fs_mgr/liblp/utility.cpp), and reject invalid slot/table sizes. Reject logical partitions containing non-linear, missing or other-device extents instead of silently dropping them and shifting the filesystem layout. Rank active plain and logical trees ahead of unslotted/inactive trees; previously an inactive plain partition could beat active vendor. Include an unslotted third label if present. Existing read-only loop/device-mapper setup remains.

3. **Preserve every manifest destination:** use a digest set for discovery but iterate the original rows when copying and counting. Both aliases of each shared digest now get populated. Skip already-correct files so a second run does not falsely signal a change.

4. **Keep split firmware coherent:** do not independently select a name-only segment whose MDT is in the manifest. A selected fallback header brings regular, non-symlink segments from its own directory, named with the manifest stem and lowercase `.bNN` suffix. This fixes Android uppercase filenames becoming unusable Linux paths. Validate little-endian ELF32 program-header bounds and the sizes of required split load/hash segments, following the pinned loader; reject incomplete/truncated/ambiguous bundles and try the next tree. Copy segments before the header. Exact-hash segments remain available, and a fallback bundle supersedes hash copies for the paths it supplies. This is structural checking, not cryptographic or hardware validation and not a transactional bundle update.

5. **Keep Android ext4 mounts read-only:** remove the initial filesystem-autodetect mount that could replay an ext4 journal with only `ro`. Try EROFS, ext4 (`ro,noload`) and FAT explicitly. [Kernel ext4 documentation](https://www.kernel.org/doc/html/latest/admin-guide/ext4.html) explains that `ro` alone can write journal recovery and that suppressing replay can expose an inconsistent unclean filesystem. No fsck or repair is attempted.

6. **Boot consumers notice replacements:** the extractor's optional `--changed-file` marker records actual writes, including name-fallback replacements at constant file count. The wrapper uses a fresh temporary marker, cleans it on exit, propagates extractor failure and retries offline remoteprocs/Wi-Fi only after changed files. Bluetooth uses `systemctl --no-block try-restart`: a synchronous wait can wait on this very unit because it is ordered before Bluetooth. Missing-file/no-change behavior still permits boot; no hardware retry success is inferred.

7. **Carry forward review 008's KWin repair:** replace the source's name-only grep guard with the exact focused two-group merge already used for Gen 3. Update base /etc and an existing persistent /etc upper, preserve unrelated keys/groups, replace stale calibration, add missing touch/pen groups independently and do not create an absent upper. This prevents a comment/partial group or upper file from hiding the intended Desktop Mode calibration.

## Limits and remaining risks

No kernel, Gamescope, InputPlumber, package, rootfs or image build ran. No installer/converter entrypoint ran, VM/container started, device partition mounted, GPT attribute written, flash or deployment occurred. Build validation remains deferred until all 109 integrations finish. **No hardware-tested claim is made.**

The source title is not a guarantee of support for every Android release. Name fallback depends on retained discoverable filenames and unambiguous directory hints. Renamed files without a known digest remain missing. Unknown/conflicting slot state, damaged/backup LP metadata, unverified LP checksums, non-linear or multi-device super layouts, retrofit slot conventions and Virtual A/B snapshot/COW state are not fully handled. Unsupported layouts must not be interpreted as successfully extracted firmware. Exact util-linux, mount helpers, Python, EROFS/device-mapper availability and their behavior in the eventual rootfs require later image validation.

Firmware scanning is bounded by the service's five-minute timeout, not a per-read deadline. Kernel I/O stalls, unmount failure, interruption between segment replacements or SIGKILL/power loss can leave partial destinations or mounts; this repair does not make updates atomic as a whole or guarantee cleanup under process death. The next normal run retries discoverable content. Firmware remains subject to secure authentication, kernel ABI/version expectations and real boot timing. Stale or higher-priority user calibration can override installer defaults; a later Gamescope SPI-association change would require rechecking double rotation. Coherent rebuilt images and device boot/Game Mode/Desktop Mode, GPU, audio, Wi-Fi and touch validation remain later work.
