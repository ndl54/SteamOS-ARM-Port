## ALSA / PipeWire behavior and limitations

The staging script masks `sm8550-audio-pipewire.service` on SM8750 and removes the inherited SteamVR WirePlumber overrides to use standard ALSA UCM discovery. The unchanged SM8750 setup helper selects HiFi/Speaker and writes only existing local speaker/headphone/capture mixers, with no DP write. The generated service retains its Elden exclusion. The common SM8550 policy helper and its EVO/UCM guards were read and left untouched; importing its pro-audio fallback into these boards would be inappropriate.

Removing HDMI from these UCM profiles prevents the normal UCM device enumeration from offering PCM3 as a monitor output. Unlike report077's mixer isolation, it removes the advertised device that userspace can probe at startup. Existing `DP0 Jack` metadata alone was not evidence that probing was sink-conditional. No replacement jack condition, monitor daemon or unverified ELD-based policy is invented.

Consequence: normal UCM monitor audio is unavailable on Odin3 and FIT Elite even with a connected audio-capable monitor. Speaker/headphone configuration remains available, but actual recovery from the upstream-reported failure is unverified. DP video is not intentionally changed. USB audio peripheral profiles and all other boards, including Pocket EVO, are untouched.

This is not kernel-level removal of PCM3 and not an access prohibition. Direct ALSA/pro-audio/manual mixer use, an alternative profile or existing restored mixer/session state can still reach the retained graph. Kernel card registration still depends on the retained DP backend/provider. Merely copying these files into a running system does not clear an already active route or demonstrate recovery; no live migration/restart operation was attempted. USB-C video success, a clean merge or presence of DP0 Jack does not prove audio health.
