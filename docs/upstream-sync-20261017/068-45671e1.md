## Review and resolution

### Preserve033 while implementing card discovery

Source068 searches `/sdcard/rocknix_abl` and `/storage/*/rocknix_abl`, adds an embedded ELF hash/length to the generated flash script, and divides flash into independent backup/write/readback lines. Its first matching directory can silently bypass original backups in a different copy; a standalone backup overwrites originals; restore can try a later folder after an earlier write failed. Nonempty files alone do not verify complete backups or ownership. The upstream write line does not check both dd statuses, and a final readback line can report success even when this run did not complete its prerequisites. These behaviors would regress033's safety implementation.

Kept the self-contained, inlined033 helper and checked action sequence. Added discovery to common preflight, independent of cwd and `$0` because the root tool may provide meaningless values. The documented internal/card locations are the only search roots; no recursive storage scan or mount operation. Paths and expanded globs remain quoted where used. A candidate is recognized by an ABL image, backup/checksum artifact, or legacy SM* backup. Restore therefore works with this device's full backup pair even if the release ELF is no longer present.

Canonicalize folders with checked `readlink -f`. Symlink aliases resolving to one path are deduplicated. More than one distinct candidate stops before partition access/writes rather than picking the first, even if one only has a partial backup or another SoC's image. A failed resolution stops. No folder is silently deleted, migrated or merged. Mount aliases that do not canonicalize to the same path can conservatively stop; the README explains this boundary and the need to identify original backups independently. Legacy backup guards now cover every SM* subfolder, avoiding a different-chip legacy backup being hidden by the current SoC choice.

Require a regular, non-symlink release image before copying it; keep the hash embedded in the generated script (`@SHA256@`) and exact nonzero length/fit checks against both partitions. The runtime snapshots and hashes the image and obtains its size from those same bytes. Thus upstream's duplicate `@ABL_SHA@` and `@ABL_BYTES@` substitutions are unnecessary. There is no new stat-derived image-size constant that can drift from the snapshot. The sidecar cannot override the embedded hash. This is regular-file type and pinned-byte validation, not an independent ELF/secure-boot verifier.

Retained Android system PATH, required-tool/property failures, SoC gate, accessible block-partition checks, canonical distinct targets and positive sizes. Added checked `stat -L -c '%t:%T'` identities so two different node paths pointing to the same block major:minor also fail. Missing/invalid stat output stops before writes. No uid wrapper is required: as in033, actual block read/write access is the privilege gate; it is not a newly claimed root-UID attestation.

### Keep the whole operation together for line-at-a-time root tools

The stager now emits a shebang plus **one physical executable line**, using shell-quoted literal source arguments to builtin `printf '%s\n'` and `eval`. Every single quote is escaped when generating that line; backslashes, dollar signs, backticks and command-substitution text in the source are preserved literally until the bundled script runs. No runtime file contents are inserted as executable code or sourced. The maintainable templates remain multiline.

This reconstructs the entire safety helper and action in one shell, including preflight, backup, sequential writes/readback, traps and exit status. It does not split safety checks and writes across separate invocations. The actual emit function and actual fill function are exercised independently in tests, including literal round-trip and fresh-shell-per-line execution. No staging entrypoint, download, package generation or build ran. Android tool line-length limits, quote handling and actual shell behavior remain untested; the generated line must stay intact.

### Original backups, checked writes and cleanup

Keep full-size per-slot backup/hash validation and preservation. Existing partial, legacy, wrong-size or bad-hash pairs fail without overwriting originals; linked backup images or checksum files now fail too. Backups in any former SM* layout also stop. New full backups must match the respective partition, are published with checksum sidecars, synced and rechecked before flashing. A partial publication is retained for recovery. Checksums are neither proof that a backup is original stock Android nor a binding to the physical device.

Restore validates and snapshots both full backups before either write. Both flash and restore use checked dd/fsync, sync, length-bounded readback and hashes, verifying A before attempting B. Failure returns nonzero, retains backups, warns that a slot may already have changed and never reports Done. Temporary cleanup deletes only the current run's mktemp directory. Cleanup failure cannot report success. No active-slot changes or automatic reboot were added. The standalone backup/restore action bodies remain byte-identical to starting main; their new discovery/identity behavior comes from the inlined helper.

Staging still retains existing backup folders rather than using upstream033's destructive recursive removal. Its output remains BOOT/rocknix_abl, called by the same two existing image recipes. Release1.2, URL, tarball digest, all four ELF digests, support labels and callers are unchanged.
