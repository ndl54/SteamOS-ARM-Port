The corresponding KWin groups also require vendor/product `0/0` plus those exact names.

`external-and-mods/kernel-tb321fu/patches/0007-input-touchscreen-add-novatek-nt36523-spi.patch` defines both exact names, allocates the input devices without assigning vendor/product (zero), and sets BUS_SPI. The touchscreen has the SPI device as its parent; the pen is separately registered without that parent. The pen rule still matches its input parent name and does not depend on SPI ancestry. The DT uses spi4, native 1600x2560 touch axes and pen support, with no touch swap/invert properties; the CSOT display panel has rotation 90.

In `external-and-mods/gamescope/src/wlserver.cpp`, `wlserver_touch_associate_connector` walks parents looking only for i2c or usb. Thus this SPI touchscreen has no associated connector; down/motion reach the common touch path without connector-driven rotation. `Backends/DRMBackend.cpp` maps right-up to orientation 270, whose touch transform is `(x,y) -> (y,1-x)`. That is exactly the source matrix `0 1 0 -1 0 1`. No Gamescope code was changed, avoiding changes to existing I2C/EVO handling.

[libinput's udev documentation](https://wayland.freedesktop.org/libinput/doc/latest/device-configuration-via-udev.html) confirms the six-number format, this matrix's 270-degree mapping, and application when a device is added. The rule establishes a libinput default, so the KWin override must replace it before KWin applies output rotation; it is not an inverse matrix to multiply by the default.

[KWin v6.3.6 connection.cpp](https://github.com/KDE/kwin/blob/v6.3.6/src/backends/libinput/connection.cpp) selects groups by Libinput/vendor/product/name. [KWin v6.3.6 device.cpp](https://github.com/KDE/kwin/blob/v6.3.6/src/backends/libinput/device.cpp) reads CalibrationMatrix as QMatrix4x4, falls back to the libinput default and sets the configured calibration with output orientation. The source's 16-value identity is consistent with that consumer. These are pinned upstream source checks, not verification of the eventual image's exact KWin/libinput binaries.

The repository's desktop-outputs helper maps right-up to Rotated270. Its kcminputrc changes affect OutputName in the user's config only when multiple panels are found; it does not install an alternative global calibration. User-specific calibration remains higher priority and is not modified here.

### Fixed: name-only guard skipped necessary Desktop Mode calibration

The source checks for any occurrence of NVTCapacitiveTouchScreen, then conditionally appends both groups together. A comment containing that name, an existing group without CalibrationMatrix, or a touch-only config suppresses the whole addition. Stale calibration is also retained. This leaves libinput's new global rotation active alongside KWin's own rotation.

The installer now merges each exact target group independently, replacing only its CalibrationMatrix with identity and adding missing groups. Other groups and other keys in the target groups are preserved. The transformation handles a missing final newline and is idempotent. It uses existing awk and the installer's existing temporary directory/trap; no new runtime helper or dependency is introduced.

### Fixed: persistent /etc file could hide the new defaults

As established in review 007 and confirmed in common initramfs, `/var/lib/overlays/etc/upper` is mounted over base /etc. A pre-existing upper `xdg/kcminputrc` hides the lower file entirely. The same focused merge now updates base /etc and an already-existing upper; it does not create an absent upper. It does not copy the base file over upper settings or edit users' home configs.
