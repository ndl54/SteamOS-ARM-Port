## Demonstrated issue and resolution

Upstream checks only the destination SH5001 config as its already-initialized marker, then copies a generated tree over the live registry. A previous partial copy can leave that config without orientation and be silently accepted on restart. Conversely, an existing calibration tree without the config gets overwritten with generated defaults. Generator failure also leaves its temporary tree behind.

Changed only the Thor registry branch:

1. Require both nonempty SH5001 config and orientation before reusing an existing registry.
2. If either is missing and any existing entry remains, fail with the registry path and preserve every byte for diagnosis/manual recovery. Do not silently regenerate over learned calibration.
3. Generate into a same-filesystem temporary directory inside a subshell with EXIT cleanup. Preserve nonzero generator/publish status.
4. Validate the two required files, remove only the still-empty destination using rmdir, and publish by `mv -T` rename. A write arriving before rmdir causes a safe failure. Failed publication remains retryable; successful restarts retain learned values.

GYRO.md documents the partial-registry behavior. The Odin persist-copy path and service listener behavior remain unchanged. No product changes outside the assigned ten paths were needed; the new regression file and this report are additional evidence.
