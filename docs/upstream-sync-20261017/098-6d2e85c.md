## Audio path, repairs and unresolved policy

The pinned common DTS selects `SM8650-APS2` via qcom SM8650/SM8450 sound-card compatibility. Speaker remains PCM1, headphones PCM0, with the same priorities, jack mute and HDMI routing. The existing setup service and shared overlay are used on multiple boards; all prior TB321FU/SM8250 early exits and SM8550/EVO UCM behavior survive the automatic merge.

1. **Exact board identity.** Upstream's model-prefix regex/shell case also accepts names such as `AYANEO Pocket S20`. UCM now tests the exact first DT compatible string `ayaneo,pocket-s2`, consistent with the pinned DTS and the kernel compander gate. The shell uses exact NUL-delimited compatible-token matching. FIT, EVO, tablets and near-matches retain their previous paths. ALSA1.2.14 sys substitution returns a C string ending at the first NUL; an unknown DTS ordering fails to select this UCM branch rather than matching a suffix board.
2. **Reachable remap.** `conf.d/sm8650/SM8650-APS2.conf` was a tracked regular copy, not a symlink. Source098 changed only the Qualcomm master file, leaving that discovery entrypoint without the new stereo remap. Replace the duplicate with a relative symlink to the canonical master. Both discovery routes now include `Speakers Digital Playback Volume`, mapping WSA_RX0/RX1 Digital Volume to separate stereo channels. Non-S2 evaluation adds no digital remap and keeps the original Speakers element.
3. **UCM sequences.** S2 exposes the new element and enables the two macro companders, setting both raw PA controls to17. Inspected ALSA-lib1.2.14 evaluator processes includes before condition branches and merges/appends the selected branch afterward. In the referenced ALSA-UCM1.2.14 files, the codec Speaker sequence enables amplifier compander/boost/DAC/PBR, disables VISENSE, and writes PA12; the S2 condition's PA17 writes follow it. Macro disable and amplifier disable sequences remain intact. UCM errors are not transactions: a successful first write is not automatically rolled back if the second fails. This is reference-source reasoning, not execution of the target ALSA parser or controls.
4. **Boot setup.** Preserve upstream's decision not to force S2 digital channels to100% after UCM success, under the exact compatible gate. Other boards retain those two commands. Failed UCM retains the existing route-only fallback. Comments no longer assert that skipping these writes causes WirePlumber to restore hardware gain.
5. **Unresolved software policy.** `53-konkr-audio.conf` still sets `api.alsa.soft-mixer=true` on `alsa_card.platform-sound`. The inspected PipeWire1.4.7 ACP `mixer_volume_init` explicitly disables hardware volume callbacks under that flag. Merely changing PlaybackMixerElem therefore cannot transfer Steam's volume bar to digital gain. The exact-FIT `konkr-volume` gate from018/037 correctly continues to exclude S2. No global soft-mixer removal or FIT-daemon activation on S2 is introduced; both would change other established behavior. A coherent S2-only hardware-mixer policy, preserving FIT/headphone behavior and tested against the installed WirePlumber/ALSA versions, remains a final-review requirement. The source's promised half-volume outcome is not delivered or claimed by this merge.

Read the current patched WSA884x mute/unmute path, including0039 and090 lifetime/fault recovery, the Linux7.2.8 WSA-macro control and sc8280xp control limits. Digital control's TLV uses -84dB plus1dB per raw step; the machine code requests a maximum of81 (-3dB), and PA limit17 maps via inverted register31-17=14 to the chip's unity gain index. These are component control values, **not calibrated total acoustic/electrical gain or protection**. On exact S2 with its compander port enabled,0039 preserves compander selection during unmute instead of forcing the fixed CSR path. No gain-limit or fault-recovery patch is changed here.

The referenced macro BootSequence writes84, while the inspected machine source caps81; actual rootfs includes/control enumeration and initialization failures must be checked later. Skipping boot100% does not guarantee a persisted or quiet digital level after UCM initialization, restart or resume. System volume remains software-controlled under the current policy. The APS2 high-pass/+8dB limiter configuration matches S2 and FIT by card; its comments about measurements are upstream claims. Its presence, peak limit, the PA value or register protection names do not establish safe S2 speaker power, thermal limits or excursion. Direct ALSA/alternate profiles can bypass user-session filtering. No replacement safe gain was invented. Existing078 Elite gain remains separate.
