## Actual path and evidence boundary

The source describes a tester's Steam library crash from a Play Store app. That crash is upstream motivation, not a device reproduction by this worker.

`apk-info` parses binary AndroidManifest.xml/resources.arsc and prints package, label and activity on three lines. `add_title` streams base/split APKs from the existing Android container, reads those lines with mapfile, falls back to Android launcher resolution, emits `konkr-android-PACKAGE.desktop`, and asks `steam_add` to add it. The helper/Steam client implementation is not present here; actual URL conversion, binary serialization, appid assignment, persistence, icon decoding and client behavior are unverified. Identity remains the package and desktop pathname, not a sanitized display name. ## Findings and resolutions

1. **Sanitization was too late for the metadata protocol.** Reproduced helper output `com.test\nFirst\nInjected\x00\x1b\ncom.test.Main\n`: the raw newline shifts mapfile's activity field before the source's filter ever runs. Move label cleaning to `apk-info` before printing; remove Unicode Cc controls (including NUL, CR/LF, ASCII DEL and C1), retain non-control Unicode and truncate to80 Unicode characters. Empty/None/control-only labels use the package. Reject malformed package identities and control characters in activities before emitting any identity lines. This validates these output fields, not the complete binary APK schema.
2. **Byte truncation can break Unicode.** Running the source's tr/cut expression against81 CJK characters under host `LC_ALL=C` produced80 bytes ending in an invalid UTF-8 sequence. The producer's Unicode slice removes the locale-dependent cut entirely. The shell uses its already-cleaned label with the existing package fallback.
3. **Desktop escape semantics.** A literal backslash followed by `n`, `r`, `t` or `s` in an APK label could be interpreted as a desktop value escape after control filtering. Escape backslashes in the Name value. Quotes, dollar expressions and percent text in the name remain data; Exec remains the fixed launcher plus package, not the label. Fixture checks include Unicode, quotes and literal `$(touch injected)` without executing it.
4. **Setup and split-icon bypasses.** Apply the source's cached-signature guard to initial Play Store setup too. `apk-info` now checks a candidate's bytes before publishing it; a `.png` containing WebP or a short/missing signature is skipped so later PNG candidates/adaptive foregrounds and split APKs can be tried. Shell guards still discard stale invalid cached files and choose `android-package-archive`. This checks the eight-byte PNG signature only; it is deliberately not claimed to validate image chunks, CRCs, dimensions or decompression safety.
5. **Partial icon publication.** Replace direct `open(..., 'wb')` publication with a same-directory unique temporary file, flush/fsync, and os.replace, cleaning up on ordinary errors. Readers see the old or new complete file. Injected fsync/replace failures preserve the old bytes and leave no temporary sibling. No backup is needed to rewrite a Steam database because no such rewrite occurs; generated icon replacement is per-file, without directory-fsync or multi-file transaction guarantees. Generated files are private to the same user's account.
6. **Wrong dynamically scoped package during icon initialization.** The declaration `local pkg="$1" ... icon="...${pkg}.png"` expands the old caller's pkg before assigning the new local. A fixture calling add_title without an outer pkg failed under nounset; an outer different pkg could name another icon. Assign icon in a separate statement after declaring pkg. The new shell fixtures deliberately have no outer pkg.

No textual merge resolution was needed. These source-level repairs preserve source102's intent while addressing the demonstrated metadata and publication defects. The old split-title test's `png\n` payload was not a PNG signature; it now uses an explicit signature fixture and asserts exact bytes rather than bypassing the new guard.

## Surrounding VDF consumers, types and remaining global-review findings

Read the neighboring implementations to distinguish this path from unrelated writers:

- `external-and-mods/NO_Steam/no_steam_games/shortcuts_vdf.py` parses nested objects, NUL-terminated strings, int32 and uint64. It can accept unterminated objects at EOF, replaces invalid UTF-8, overwrites duplicate keys in dictionaries, and does not validate the full root/entry schema. Its serializer emits all Python integers as int32 (so parsed uint64 values are not type-preserving), permits embedded NUL strings, and errors on other types. `add_shortcut` also repairs all entries' path fields, writes a `.vdf.bak`, then directly truncates/writes the target without atomic replacement or Steam/concurrent-writer lock. CLI repair writes without that backup. These are preexisting preservation/concurrency risks in a separate user-invoked app;102 never calls or edits it.
- Emulator Hub's `vdf_read`/`vdf_write` support objects/strings/int32, with no complete size/type/schema validation; malformed shapes or field conversions can escape the limited exception handling. `flush_shortcuts_offline` directly writes, has no VDF backup or cross-process Steam lock, reindexes entries and marks app state before final file publication. Its callers check Steam running, but Steam can start after that check. The running-client path in `Decky/common/loadout/dist/index.js` uses SteamClient.Apps.AddShortcut/RemoveShortcut, with separate bookkeeping/error limitations. Neither path is used by `konkr-apk`.
- The dualscreen dashboard only reads VDF for recents. Its parser/consumer can accept truncated integer bytes and lacks full validation of root/entry shapes and numeric fields. It writes no library. The separate LSFG Steam service reader bounds integer reads, rejects trailing/unterminated objects and checks shortcut types; these safeguards do not make the other consumers safe.

These observations are source findings for a separately scoped global review, not an excuse to rewrite unrelated libraries in102. No serializer was exercised against real userdata. The tests' unrelated desktop and binary-library sentinels remain byte-identical.

Android's raw grep confirmation can match another user's file or coincidental bytes and does not prove schema validity or a durable Steam save. `titles` is an advisory local marker; failed Steam addition does not append it, and later sync retries, but add_title intentionally returns success after an unconfirmed title attempt so an installed app is not treated as uninstalled. Metadata/icon extraction errors are tolerated with fallback. Desktop and marker writes still have existing direct-write/concurrency limitations. There is no new lock spanning setup, daemon sync, install and Steam; complete icon replacements are last-writer-wins, and signal/power loss can leave a temporary icon. Existing malformed APK chunk sizes/resource references can still raise errors or stall the minimal parser; full hostile-APK validation, limits and timeout handling are outside this name/icon patch.
