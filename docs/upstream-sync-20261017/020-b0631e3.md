## Desktop Mode lifecycle

The common initramfs parses only the exact whitespace-delimited token `steamos.session=plasma`. This selects a session independently of debugging: it neither enables the collector nor takes over the console. `steamos.screenlog=1` still activates debug separately. Combining both intentionally stops the Desktop session for the screen report.

After mounting the selected root, update recovery and the early `/etc` overlay attempt, init writes its own `sddm.conf.d/zzz-steamos-arm-session.conf` with `[Autologin]` and `Session=plasma.desktop`. It leaves the configured user and other SDDM settings alone. On the next boot **through this updated common initramfs**, absence of the exact token removes this managed override. This is persistent filesystem configuration cleaned at the next eligible boot, not a RAM-only file or a one-time SDDM login transaction. Booting a different/older initramfs can leave it in place; within the selected boot it can continue overriding subsequent SDDM autologins/session changes. No stock default is rewritten by this patch.

SDDM loads vendor snippets, then `/etc/sddm.conf.d` snippets, then `/etc/sddm.conf`; the last file can override a snippet. The `zzz` name follows ordinary SteamOS snippet names but cannot guarantee precedence over arbitrary later custom settings. This follows the [SDDM v0.21.0 configuration loader](https://raw.githubusercontent.com/sddm/sddm/v0.21.0/src/common/ConfigReader.cpp), not execution of the final image's SDDM. Existing autologin user configuration and an installed working Plasma session are prerequisites.

Both overlay installers install `/usr/share/wayland-sessions/plasma.desktop`. Its Exec invokes `/usr/lib/steamos/sm8550-startplasma`, which runs environment preparation, desktop-outputs, optional desktop-fit, then startplasma-wayland. Thus direct SDDM selection still uses the existing cleanup/layout wrapper, rather than bypassing it. The unchanged desktop-outputs policy reads panel orientation/modes, chooses scale and the existing 60-Hz preference when available, and preserves user-modified layouts. Game Mode display arguments, fork display defaults and exact EVO gates remain unchanged. The existing steamos-session-select/steamosctl wrapper is not called by this boot switch.

The common builder and the SM8550 importer package this initramfs and bootdebug. The session switch requires that updated initramfs to execute; merely installing the collector into a rootfs with another initramfs does not add Desktop selection. No kernel recipe/cmdline default enables the new token.

## Display report paths and timing

The exact screenlog gate, tty1 character-device check and successful console open precede any delay, debugfs access or graphical-session stop. The worker waits 70 seconds from its own start, tries to mount debugfs if needed, and concatenates `/sys/kernel/debug/dri/*/state` into `/run/steamos-arm-kms-state.txt`, including read errors. It waits another five seconds, stops display-manager, waits three seconds, switches VT and renders three pages with 30-second pauses. Capture/read/stop/query durations add to those waits; neither uptime-75 takeover nor a globally atomic multi-card snapshot is promised.

Page 1 retains firmware/kernel/failed-unit/panel diagnostics. Page 2 retains the first 75 filtered current-boot UID 1000 messages. Page 3 reuses the saved pre-stop KMS state; it does not reread fbcon state after takeover. It selects planes with a non-null CRTC, framebuffer/format/modifier/geometry/rotation fields, then CRTC and connector fields. The filter matches the plane/CRTC naming and tab-indented fields in the [Linux DRM atomic state printer](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/drm_atomic.c). This is a software atomic-state diagnostic, not proof of photons on a panel or successful scanout. Exact target-kernel extensions remain unverified. Limits stay 75 selected lines and 118 characters per line; multiple cards and large states may truncate.

The raw KMS capture lives only in `/run`; this source does not copy it into BOOT/USB debug-logs. The existing file collector still uses `/boot/debug-logs` or its owned USB fallback, with early boot snapshots on their previous paths. Console reporting and file capture run independently; collector exit/USB cleanup complete before the parent waits for the report. The generated Type=simple service and fallback service retain their activation and duplicate-start suppression from 012. Explicit screenlog still keeps the service alive after file capture.

Capture the bounded filtered output and emit an explicit unavailable-state message when that output is empty, also covering absent/empty captures. Retain raw bytes/errors for inspection. The original error-only blank page was reproduced. Relabel page 3 as state before console takeover so combining Desktop and screenlog does not falsely label Plasma state as Game Mode.

## Limits and remaining risks

Real BusyBox execution, OverlayFS whiteout handling/late mount, SDDM version/config precedence/autologin and Desktop startup need later image/device checks.
