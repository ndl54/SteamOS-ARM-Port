## Overlay path and coordinates

The session discovers the largest connected internal DSI/eDP mode, converts portrait panel dimensions to landscape W/H, and permits existing GAMESCOPE_WIDTH/HEIGHT overrides. These dimensions are passed as both output and nested dimensions. The new policy runs after this setup and before Gamescope starts: when Mangoapp is enabled, inherited MANGOHUD_CONFIG is empty/unset, and H > 1200, export `read_cfg,font_scale=H/800` rounded to one decimal. H=1200 remains unchanged; 1440 gives 1.8, 1600 gives 2.0, 1904 gives 2.4, and 2160 gives 2.7. Default EVO 1920x1080 logical geometry does not activate it. A user-specified nonempty configuration remains authoritative, even if it contains no font_scale.

The policy uses logical session H, not physical panel height, DPI or a measured screen size. The existing DRM mode/orientation path transposes output width/height at 90/270 degrees and flips in place at 180 degrees; shader/KMS rotation decisions are unchanged. Gamescope paints the external overlay with NoScale/NoFilter against output coordinates, so increasing Mangoapp's own font scale is distinct from scaling the game or altering input transforms. This change does not add an overlay coordinate transform.

The vendored MangoHud parser in `src/overlay_params.cpp` first reads environment options, uses read_cfg to load the preset/config file, then reapplies environment options. `font.cpp` and `overlay.cpp` apply font_scale through ImGui's FontGlobalScale; default computed HUD width also uses it. `overlay.cpp::position_layer` still positions the HUD from its window size, display dimensions, margins and configured offsets. Preset changes and no_display remain available through MANGOHUD_CONFIGFILE; scale overrides a font_scale in that file, while other preset settings remain available. The existing Gamescope `mangoapp_config.h` visibility parser also understands read_cfg.

The new variable is inherited directly by Gamescope and its Mangoapp child and added to the existing gamescope-steam.env filter for steam.service's EnvironmentFile. The SM8550/pinned-Turnip Mangoapp wrapper does not unset these variables. Existing session readiness, preset path reuse, Steam service ordering and environment handoff mechanisms are unchanged; no systemd service was run to validate them here.

**Limitations:** this is startup scaling, not dynamic per-monitor scaling. Explicit GAMESCOPE_OUTPUT currently skips mode discovery; width/height overrides, forced orientation differing from the normal landscape assumption, output hotplug, and per-connector Mangoapp instances can diverge from the startup H. All instances inherit one scale. Existing fixed/explicit HUD dimensions and margins need visual checks with Steam presets, especially horizontal layouts. ## Xwayland lifecycle, ownership and repair

`xwayland_surface_commit` locks the texture buffer and calls PrepareCommit. PrepareCommit transfers presentation-feedback resource pointers from the live surface into ResListEntry_t, extracts shared acquire/release timeline points, and clears the surface's per-commit metadata. A valid X11 owner receives the entry through wayland_commit under its queue mutex, followed by a compositor nudge. XDG commits and not-yet-associated surfaces retain their existing separate queue paths.

The source replaces three assertions with guarded forwarding or buffer unlock: immediate X11 commit, pending entries during content override, and pending entries during surface association. The outer `if (x11_surface)` already protects the override branch, so removing its redundant inner assertion introduces no null dereference there. Association drains matching pending entries before the override handler's second loop, so the second loop normally has nothing further to forward; neither path now double-unlocks an entry. Entries forwarded to the queue retain their buffer lock and shared state for the normal consumer. Discarded pending entries are erased and their local moved entry is destroyed once.

**Repair 1 — complete discard ownership.** Unlock alone leaks the presentation-feedback resources moved off the surface and leaves the client without a discarded event. ResListEntry_t owns a vector of raw wl_resource pointers, whose vector destructor does not destroy the resources. Added a shared `discard_unroutable_x11_commit` helper at all three new drop sites. It asserts the existing Wayland lock contract, sends discarded/destroys the feedback through the existing helper while the surface is live, then unlocks the one buffer lock. The local entry subsequently destroys its shared metadata and timeline points. CReleaseTimelinePoint signals its release point on destruction; no compositor/GPU submission was made for this dropped entry. Acquire points are not waited on by this discard path. No fake presentation success/timing or KMS completion is emitted.

The Wayland event dispatch holds the Wayland lock, and the association function already asserts the same lock. A once-per-process warning reports the missing owner without flooding every frame. Successful forwarding, normal compositor import and inflight ownership are unchanged. No new queue/mutex or retry thread is introduced.

**Scope of the wake claim:** this avoids the specific assertion/null dereference when the surface-info owner pointer is null. The reviewed normal initialization/set-ID paths assign that owner; finish unlinks surfaces and does not generally clear the owner pointer. The inner wlr_xwayland_server pointer is a separate lifetime. Source inspection does not establish that normal suspend makes this owner null, and this is not a recovery/restart mechanism for a destroyed Xwayland process or a non-null dangling pointer. Existing surface/server teardown assumptions and frame-callback progress still require runtime validation. The pre-existing pending-surface destruction path's feedback ownership is not changed by this narrowly scoped helper and is not certified safe here.

## Locale repair

**Repair 2 — locale-independent config number.** The source's awk printf respects LC_NUMERIC. Running its actual shell fragment with H=1904 and `LC_ALL=de_DE.UTF-8` produced `read_cfg,font_scale=2,4`. MangoHud uses commas as option separators, so this is not the intended 2.4 scale. Restrict the awk invocation to LC_ALL=C, producing a decimal point without changing the session's locale. The source behavior, read_cfg and custom-config precedence are otherwise retained.

## DRM/KMS and earlier fork work

The source does not change DRM atomic commit handling. Reviewed the prepare/fallback, Commit, page-flip completion, state rollback and lease paths:

- Prepare treats -EACCES as unavailable/VT-switched output; failed composition preparation retains its existing previous-mode retry and dirty-state/re-poll behavior.
- Before a page flip, the backend increments the pending count and transfers request framebuffer references into the queued list. Successful atomic commits advance current state; the matching page-flip handler moves queued references to visible, clears old references, decrements/notifies the pending count, updates timing and nudges the compositor.
- -EBUSY/-EACCES retain rollback, queued-reference restoration/clear and counter rollback. Other atomic flip errors still log and abort. This integration does not make EINVAL/EIO or other unrecoverable errors silently succeed.
- The existing atomic wait for page-flip completion, CRTC/event matching, lease yield/park/resume and teardown paths are unchanged. Missing events, stale ownership and suspend/hotplug behavior remain device/runtime concerns; the new Wayland guard does not resolve them.
