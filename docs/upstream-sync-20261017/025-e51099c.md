## Findings and integration

### Payload provenance and packaging

The source copies an arbitrary `INITRAMFS_HOTFIX` tree directly into `/hotfix`, without validating names, types or permission metadata. Runtime only enumerates regular files, so symlink payload entries are silently ignored; host paths containing newlines are incompatible with both its line-based traversal and existing cpio invocation. A relative/container-invisible path can also identify the wrong input or fail late. A source inside the initramfs work directory can be deleted by staging cleanup before it is copied.

Added `hotfix-tree.py`, invoked only when `INITRAMFS_HOTFIX` is nonempty. It validates before staging cleanup, rejects overlap with the initramfs staging tree in either direction, and revalidates when copying. It accepts nonempty regular-file payloads under canonical `etc/` and `usr/` paths; only existing installed regular files may be replaced under `usr/`, while `etc/` can also contain new files. This intentionally narrows the upstream arbitrary-root contract: use `usr/bin`, `usr/lib`, etc., not merged-/usr aliases such as `bin` or `lib`. Other top-level roots are rejected, not silently skipped.

Validation rejects payload symlinks (including directory links), special nodes, control characters/newlines/backslashes and unsupported filename characters, setuid/setgid files and group/world-writable files. Spaces and conventional ASCII package filename characters remain supported. The init-managed Desktop override and generated collector paths are reserved. Directory traversal errors abort instead of dropping unreadable subtrees. Only bytes and ordinary permission bits are staged; host ownership, xattrs/ACLs/capabilities and hard-link topology are not copied. Existing cpio root ownership remains in place. SHA-256 and mode manifests sit beside `/hotfix`; the runtime helper verifies content before and after copying into RAM and retains manifests for inspection.

These manifests identify payload bytes/modes, not a signed origin, expected installed-base version, or review approval. `INITRAMFS_HOTFIX` remains a trusted operator-controlled build input which must remain stable while staging; this is not a sandbox for adversarial concurrently changing source trees. There is no download or automatic selection of a payload.

The GCC wrapper preserves `CROSS_COMPILE`, `FRAME_FW_DIR`, cross-toolchain selection, configurable container engine and existing flags, adding `INITRAMFS_HOTFIX` to the forwarded environment. It resolves a relative payload path on the host and requires the canonical directory to be strictly inside canonical MOUNT, rejecting a symlink escape or an inaccessible/missing directory before container launch. The wrapper still assumes its existing MOUNT/HERE contract. Common builds without the variable clear old staging normally and carry no payload/helper. The separate SM8550 prebuilt importer does not implement this optional input and remains unchanged; its ordinary initramfs has no `/hotfix` and therefore never calls the new helper.

### Runtime, order, paths and reversibility

The upstream implementation persistently stages bytes under `/var/lib/steamos-arm/hotfix`, uses `rm -rf` there, follows installed target symlinks through `test -f` and mount, and copies missing `/etc` files onto the persistent filesystem/overlay. New files therefore survive a later ordinary boot, contradicting the stated per-image behavior. Copy/mount failures can yield a partially applied boot without failing init. Reproduced the persistent-new-file and symlink mount-target problems with temporary directories and mocked mounts.

Added `initramfs/apply-hotfix` and replaced that block with a checked helper call. Order remains: mount selected root, perform pending update recovery, attempt persistent `/etc` overlay, create/remove the managed Desktop override (including pending-upper cleanup), apply hotfix, configure the debug collector, then switch_root. The previous init is byte-identical after removing the new helper-call block.

The helper preflights every payload entry and every target component, rejecting existing or dangling symlinks and non-directory parents rather than resolving absolute rootfs links in the initramfs namespace. Missing `/usr` files and non-file destinations fail explicitly. If an `/etc` payload exists and a configured persistent `/etc` overlay failed to mount, the test boot stops rather than applying into a base which a later etc.mount could hide. Ordinary boots and bypassed hotfix boots retain the prior deferred-overlay behavior.

Payload storage is a private root-level tmpfs at `/.steamos-arm-hotfix`, outside `/run` and `/var` which may be overmounted during handover. It is mounted mode 0700 with nosuid/nodev, while executable file bits remain available for bind targets. An existing backing mountpoint must be an empty root-owned mode-0700 directory, never a symlink. No persistent payload files are recursively removed or overwritten. Only the empty mountpoint directory remains on disk after reboot.

Existing `/usr` files are individually bind-mounted from this RAM copy. When the payload includes `/etc` files, the helper first snapshots the already-visible `/etc` into RAM, copies the validated replacements/additions into that snapshot, then bind-mounts the prepared directory over `/etc`. This avoids both persistent placeholders and an additional OverlayFS stack. Existing unrelated `/etc` files, symlinks and masks are copied without dereferencing links; new parent directories are traversable mode 0755, and replacement file modes are retained. Removing a private snapshot destination before copying breaks any hard-link alias within that snapshot.

**All `/etc` changes made during a boot with an `/etc` hotfix are transient**, including unrelated configuration changes made after login. This is an explicit test-image tradeoff, not production configuration persistence. A payload containing only `/usr` replacements leaves `/etc` behavior unchanged. Rebooting an image without the payload, or bypassing it with the exact whitespace-delimited token `steamos.hotfix=0`, exposes the installed files again. The image carrying the payload is the normal opt-in; no recipe or cmdline default enables it. Rebooting the same test image without that disable token reapplies it. Bootloaders with forced cmdlines must actually deliver the disable token, or recovery requires choosing a payload-free image.

Every preparation, checksum, copy or mount failure returns nonzero; init snapshots HOTFIX FAILED, prints the bypass instruction and stops in its rescue shell. It does not claim successful application or enter systemd with an unnoticed partial set. A failure after some bind mounts leaves those mounts available for inspection in the stopped boot; there is no automatic rollback transaction. Reboot removes the tmpfs/binds. Do not treat file bind mounts as a guarantee that an in-place package update can replace a mounted path: such writes/renames can fail or affect the transient copy. Use a normal image/bypass for durable system updates. Pending recovery is deliberately completed before any hotfix mount.
