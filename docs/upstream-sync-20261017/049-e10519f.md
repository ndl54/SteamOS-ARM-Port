## Necessary resolutions

1. Treat old/quoted overlay loops as alternatives. Applying two independent mandatory-looking patches generated a false warning on every valid version. Select the known old or already-patched spelling, patch idempotently, and emit one warning only for unknown syntax. Preserve original quoting and extra-overlay ordering.
2. Keep SSH option splitting predictable. Preserve the source's shared SSH/SCP options while disabling pathname expansion during whitespace splitting. Document that shell quoting inside the environment string is unsupported. No eval or new secret/config storage.
3. Reject empty/path-bearing framework image versions before constructing the output directory. Accept a single alphanumeric-led version component including dots, hyphens and underscores. Both plain and v-prefixed versions work; slash/newline paths fail before local payload mutation.
4. Propagate remote failures. Add `set -e` to the remote command body; previously a failed copy or compiler could be followed by later successful commands and an apparently successful SSH status. The outer local pipefail already protects transfer/extraction errors.
5. Preserve existing generated framework on failure. Extract into a fresh sibling, remove AppleDouble, and check the numeric count before replacing the old output. Rename the old payload to a recoverable sibling, publish the new directory, restore the old one if publishing fails, and delete the backup only after success. Failed extraction/count validation leaves the old directory untouched. The temporary staging directory is cleaned on ordinary exit.
6. Preserve account data when inspection fails. The existing negated dumpsys/grep pipeline treated a failed account query as absence of Google and invoked pm clear. Capture the dump and require a successful, recognizable account count. Only an explicitly empty account listing can trigger the existing first-identity-migration cleanup; any nonzero count or Account record keeps data, even if account details are omitted/redacted. Failed/unrecognized output keeps data and the old revision marker so a later start retries. Existing signed-in accounts, user config, shared Android data paths and SteamVR config behavior remain intact.
