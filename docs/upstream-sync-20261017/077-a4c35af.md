## UCM repair and policy

Upstream adds the DP `cset` to the **common HiFi EnableSequence** on both boards. A missing/rejected DP control can therefore fail activation before the shared codec setup completes, even when the user only wants speakers/headphones. [ALSA lib v1.2.14 sequence execution](https://github.com/alsa-project/alsa-lib/blob/v1.2.14/src/ucm/main.c) propagates control errors; `set_verb` only activates the verb when execution succeeds. This is source evidence, not a runtime reproduction with the image's ALSA version.

Moved that one mixer enable into `SectionDevice."HDMI".EnableSequence`, with a matching mixer-disable sequence. The common verb and every pre-existing speaker/headphone sequence/value now remain byte-for-byte equal to starting main. Thus normal common initialization does not depend on the new mixer; HDMI selection still reports its own error. Disabling HDMI relinquishes its route instead of leaving it permanently connected. No ignored-error fallback is added.

Preserved upstream's PCM 3, two channels, priority 200, default mixer, `DP0 Jack` and `JackHWMute Speaker`. Speaker priority 100 and headphone priority 200 remain; headphones and HDMI tie, so policy/default choice depends on session-manager state. No forced default output is added. JackHWMute is policy metadata, not evidence of a physical mute circuit or measured silence. No explicit ELDDevice or capture device is introduced. The topology's existing capture PCM remains but this change does not add a microphone UCM device.

WirePlumber/PipeWire own device selection and hotplug policy; existing setup service, buffers, user settings, limiter-related staging and shared codec includes are untouched. Real UCM parsing, transitive includes, jack/mixer enumeration, profile probing and fallback are not validated here. A failed HDMI probe or DSP path can still affect profile usability; moving the mixer is narrower than guaranteeing complete audio fault isolation.

## Clocks, hotplug, suspend, errors and ownership

The reconstructed q6apm-lpass path sets DP index 0, channel allocation and stereo mapping. AudioReach sends hardware endpoint media format and DisplayPort interface parameters (MST index 0) to ADSP. Graph-open rejection still propagates through existing local patch 0015; graph configuration/preparation errors are returned and existing graph close paths remain. Existing local 0016 owns stream/port release and restoration across suspend; local 0014 enables card PM and clears ignore_suspend. No new worker, raw pointer owner or clock provider is added by 077.

The inspected DP driver derives link rate/lane count from the enabled display and notifies HDMI-codec on connect. HDMI-codec reads ELD, constrains capabilities and serializes its single stream; the jack callback reports availability. The existing local 0026 returns success without register programming when DP power is off. That guards unclocked access at that point; it does **not** prove that DSP graph start, codec probing or later hotplug succeeds. When active, audio prepare programs SDP/ACR and marks audio enabled. Shutdown disables audio and signals completion; display disable can wait up to five seconds for audio teardown. Unplug, no-audio monitors, display-off playback, suspend/resume, simultaneous outputs and race behavior need real validation. No broad existing driver rewrite is mixed into this item.
