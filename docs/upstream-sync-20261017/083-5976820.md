## Findings and repairs

1. **Missing zone LEDs.** The source globs omit the `rgb:lN`/`rgb:rN` layouts already managed by the daemon. The new helper handles joint `*joysticks*`, exact left/right-joystick and numeric RGB zones, leaving power/keyboard/unrelated LEDs alone. The assigned source was exercised against temporary files and demonstrably left a zone lit.
2. **Daemon can relight after blanking.** SIGHUP/profile actions and periodic battery/heat colors can write before the system freezer runs. An extracted original daemon method reproduced relighting after the source's blank. The new `stick_sleep.py` serializes the entire daemon stick update against snapshot/blank/restore with a shared flock. The snapshot is published atomically before hardware mutation and doubles as the asleep marker. Updates suppressed while asleep are retained as pending and retried from the existing one-second loop with current configuration. Daemon lock acquisition is nonblocking so waiting for sleep I/O cannot stall fan/control processing. In-flight daemon updates finish before blanking takes the lock.
3. **Restoration cannot depend only on a running daemon.** Save brightness, optional effect arguments and optional active trigger identity before modifying anything. Disable a trigger, zero brightness before selecting static (avoiding the source's transient old-brightness static write), then restore brightness, effect and trigger in that order. Multi-intensity and persistent user settings are never edited. Repeated pre retains the original snapshot; unpaired/repeated post is a no-op. Normal post restores even without a daemon; the existing HUP and deferred retry apply newer daemon configuration if changed during sleep.
4. **Preparation failure/timeout needs cleanup.** Added idempotent ExecStopPost invoking only the common LED restore helper. [systemd.service documentation](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) specifies that ExecStop is skipped after startup failure/timeout, whereas ExecStopPost runs for cleanup. Normal post restores first; the fallback handles an incomplete pre or interrupted post. This is source/configuration reasoning, not an executed systemd transaction.
5. **Delivery dependencies.** Full overlay copy already carries the new module beside the daemon. The explicit EVO repack copy/manifest previously carried only common sleep; it now also carries the paired module, daemon and base unit before applying the existing EVO drop-in. Repack/build/install entrypoints were read and syntax-checked only, never executed.

The runtime journal is root-directory-contained under /run and only permits selected basenames and known attributes on read. Snapshot publication failure leaves LEDs unchanged. Per-LED read/blank/restore errors are logged and do not prevent processing other LEDs or other device recovery. Restore releases the marker even after an individual I/O failure so the daemon can retry its configuration. Missing attributes are opened without creation. Corrupt journals cannot redirect restoration outside recognized LED basenames; post releases them for daemon recovery. No guarantee is made for recovery without a running daemon after a hardware write failure.
