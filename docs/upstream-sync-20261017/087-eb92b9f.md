### PMIC, IRQ, wakeup and time offset

Read the pinned [Linux 7.2.8 PM8xxx RTC driver](https://raw.githubusercontent.com/gregkh/linux/v7.2.8/drivers/rtc/rtc-pm8xxx.c), its 7.1.2 counterpart (byte-identical), PMK8550 DTS, RTC binding and RTC sysfs implementation at both versions. The PMK8550 node uses `qcom,pmk8350-rtc`, RTC/alarm register regions 0x6100/0x6200 and rising-edge interrupt `<0x0 0x62 0x1 IRQ_TYPE_EDGE_RISING>`; no new interrupt is invented by this change.

With no-alarm present the driver does not acquire the alarm IRQ and clears RTC_FEATURE_ALARM. Removing the property enables IRQ acquisition, the alarm handler, managed wake IRQ registration and managed device wake initialization. RTC sysfs exposes wakealarm only for a wake-capable parent with alarm support. An extra wakeup-source property is unnecessary for this driver path. Successful IRQ mapping/request and offset probe remain prerequisites: a failure can now fail RTC probe instead of registering an alarm-less clock.

The driver subtracts the retained SDAM offset when programming alarm registers and adds it when reading back, matching its RTC time conversion. Its interrupt handler reports RTC_AF and disables/acknowledges the alarm. No allow-set-time property or raw counter ownership change is introduced. DT removal requests Linux alarm ownership; it does not reconfigure secure firmware/SPMI peripheral permissions or prove ADSP relinquishment. Upstream's comment that nothing on the DSP uses it is an assumption not independently established by this source review. The DT still loads signed ADSP firmware; actual peripheral/IRQ ownership and audio/sensor coexistence must be checked on FIT and S2 hardware later.
