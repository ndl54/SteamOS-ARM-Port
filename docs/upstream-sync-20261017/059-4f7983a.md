Normal EVO/Elden image recipes do not automatically select this path. The package includes Image, PC adb installer, repacker, firmware manifest and KernelSU module. No image/package has been produced in this review.

PC firmware processing now fails on digest mismatches as well as missing files, validates little-endian ELF program-header/segment bounds, and extracts source archives only as bounded regular files with safe paths. The former warning-only mismatched-firmware acceptance is gone. The new early import unit follows remount-fs rather than local-fs, avoiding the local-fs/udev coldplug ordering trap documented in the pinned platform's own gen-ids unit. These are source ordering decisions, not a tested systemd boot transaction. Existing057 Elden extraction/retryable first-audio reboot code is untouched.

## Exact board and storage isolation

The common initramfs has a narrowly gated Baldur branch: require root=PARTLABEL=steamos-gen5, globally unique root/log labels, partition2/1 on one physical SD parent. USB/UFS label collisions, duplicate labels, eMMC and unknown layouts fail discovery. Other boards retain their old branches. On Baldur only, the early live debug logger does not retain the logs mount across switch_root, because early firmware import needs to acquire that partition. Normal early snapshots still run; other boards' live logger remains unchanged. A separately owned late debug/log mount can cause the conservative runtime guard to refuse access.

Kept `tablet-storage`, `tablet-slot`, `tablet-sd-grow` and Elden's SD-grow unit **unchanged**. Dedicated `gen5-storage` loads a private instance of the read-only identity/table/backup primitives with an exact Baldur predicate; it never calls Elden's slot switch or single-partition grow mutations. There is no SoC-based expansion of Elden helpers. Gen5 root growth accepts only its two-entry GPT card, matching node/parent/number/label/type/UUID/geometry; it retains CID/major:minor, writable direct ext4, mount/swap/holder/loop checks and verifies the table. Only partition2 size and nonshrinking GPT last-LBA can change; partition1 is preserved. Backups precede the write; readback precedes partx/kernel-size verification and resize2fs. Every failure propagates, without a success marker; markers include actual card/table/filesystem identity. No forced unmount, shrink or whole-table rollback.

Linux return to Android requires exact Baldur, direct SD root, unique same-UFS boot slots, no UFS mounts/holders/loop users, matching sizes/geometry/magic, and unambiguous active A. It verifies the saved full boot_b hash, saves and verifies boot_a into a unique root-only directory, revalidates, copies, flushes buffers, verifies boot_a and only then requests reboot. It never edits active-slot GPT bits. The existing shared lock serializes cooperating Linux GPT/Gen5 operations. --check is read-only and never invokes pkexec; Decky exposes the button only after the matching helper succeeds, with missing-helper/timeout/error handling outside its event loop.

Android-side installer and KernelSU Action share `storage.sh` and a lock directory under the root-only Gen5 state directory. They require exact DT Baldur and active Android slot A, unique equal-size boot partitions on one UFS ancestor, no target mounts/holders/block loops, and refuse active swap/unresolved loop paths. Android's UFS device has other mounted partitions by design, so these checks cover the **boot targets**, not an impossible requirement to unmount all Android. Firmware card staging separately requires unique labels on one SD parent, correct partition numbers and unused targets. It uses a unique owned mount and stops on mount/copy/hash/unmount failures; the old semicolon cleanup could report success after a failed mount/copy or module install.

First install preserves original boot_b and stock Android boot_a on the PC, verifies hashes and the v4 repacker self-test before replacing B. KernelSU uses the canonical saved hash in `/data/adb/steamos-gen5`, fixing `--switch`'s missing action-directory android.sha256. Action checks full image size/hash/magic, preserves old A, revalidates, writes, flushes and reads back. Removed the source's unchecked restoration followed by the false message “nothing changed.” Failed writes/readbacks retain backup and do not reboot; no automatic restoration is claimed. Module-install failure is no longer hidden by a succeeding rm. Boot-repack now rejects truncated header/kernel/vbmeta/signature bounds while preserving the stock authentication blobs and exact full partition length.

The package builder now refuses an existing output directory, allocates a unique mountpoint and explicit owned loops, and cleans only those resources. Unmount/detach failure retains resources/output and fails; no unconditional unmount of shared `/mnt/gen5`, output deletion while mounted, or loss of an unrelated owner. Card creation and installer operations are source code only in this review.
