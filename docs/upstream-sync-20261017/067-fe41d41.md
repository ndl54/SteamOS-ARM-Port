## Sleep diagnostics: measurement and passive behavior

The new executable is installed by both common and SM8750 overlay scripts under system-sleep. [systemd's documented hook interface](https://www.freedesktop.org/software/systemd/man/latest/systemd-suspend.service.html) supplies pre/post and the sleep action; hooks run in parallel. The actual common wrapper invokes systemd-sleep for s2idle but directly invokes konkr-standby otherwise. Consequently the new hook can observe s2idle on EVO despite its service drop-in replacing the common preparation helper; it does **not** measure the custom standby path. It requires no new preparation/recovery call in either helper.

The source mounted debugfs, read each counter twice, assumed19.2MHz, used signed shell arithmetic on unsigned counters, used wall time and called the entire hook interval sleep. Its glob also included `ddr_stats`. The reviewed [Linux qcom_stats driver](https://raw.githubusercontent.com/torvalds/linux/master/drivers/soc/qcom/qcom_stats.c) exposes Count as u32 and Accumulated Duration as u64, and adjusts duration for a subsystem currently asleep. Its separate `ddr_stats` read can send a QMP freqsync command. This reference explains the format and side effect; it is not proof of every target kernel's exact implementation.

Replaced that shell hook with bounded-name Python diagnostics:

1. Never mount debugfs or write sysfs/firmware/sleep controls. Read only known passive SoC/subsystem stat names, skipping symlinks, `ddr_stats` and unknown files. Missing stats produce a diagnostic and no sample. Python3 is already used by image runtime helpers.
2. Read each counter file once, validate exactly one unsigned count/duration within32/64-bit bounds, and report unreadable/malformed entries without inventing zeros. Keep durations as raw ticks instead of an unverified timer-frequency conversion.
3. Use CLOCK_BOOTTIME for the pre/post interval, which includes suspend and is unaffected by wall-clock adjustment. Label it **hook interval**, including overhead/failed attempts; do not claim residency, sleep success or a percentage.
4. Publish one root-only temporary JSON snapshot atomically under/run with boot/action identity. Clear an older pre before a new attempt and consume post state once, including malformed state. Failed publication cleans its temporary file and cannot reuse the prior sample. Validate saved numeric structure before arithmetic.
5. Report decreasing counters as `reset-or-wrap` without a delta because reset and rollover cannot be distinguished from two readings. Python preserves unsigned64 values beyond signed shell range. Missing/new counters are `unpaired`.
6. Log the kernel's **last wake IRQ**, with optional name, not a proven cause of this attempt. Zero/missing/invalid IRQ is unknown. Read/parse errors remain diagnostic and return0; there is no suspend veto or retry/recovery operation.

Existing EVO exact `ayaneo,pocketevo` dispatch, bound UFS, ownership journal/storage exclusion, USB-before-MCU recovery and Wi-Fi module-restore-before-scan were traced and remain unchanged. The separate Android LED service/protocol is untouched. The common036/042 sleep policies are untouched. Parallel diagnostic sampling establishes no new ordering against Wi-Fi/LED hooks and does not replace them.
