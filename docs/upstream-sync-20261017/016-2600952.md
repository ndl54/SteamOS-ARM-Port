## Review and runtime trace

The sole product change replaces `umask=0077` with `umask=0022` in the TB321FU converter's generated `/boot` fstab entry, plus its explanatory comment. It retains the exact device gate, `/dev/disk/by-partlabel/super`, `vfat`, `loop`, `defaults`, `nofail`, and `0 0` fields.

[Linux VFAT documentation](https://docs.kernel.org/filesystems/vfat.html) specifies that the mask applies to both files and directories, and default uid/gid come from the mounting process. In the expected root/systemd mount path, ownership remains root; 0022 allows ordinary users to read files and traverse/list directories while masking group/other writes. This is a filesystem-wide policy, including boot assets and logs, rather than a per-directory chmod. The source retains default execute-bit behavior; it does not introduce separate fmask/dmask or promise mode 0644 for every regular file. No user ownership or user-mount option is added.

The converter builds the Gen 3 FAT super image with Image, DTBs, GRUB menus and a `debug` trigger. Its one-stage menu passes `root=PARTLABEL=userdata` and `steamos.bootlabel=super`. Common initramfs resolves those partition labels, mounts super at its own `/boot` (normal FAT mount followed by review 005's explicit BusyBox loop fallback), and mounts userdata at `/newroot`. Early `bootlog.txt` and rotating `bootlog-live-*.txt` reside at the FAT root. The live logger can retain its mount for five minutes across switch_root; it is not a move of that mount into `/newroot/boot`.

After switch_root, the real system mounts super at `/boot` through fstab. The converter writes identical fstab content into base `/etc` and an existing `/var/lib/overlays/etc/upper`; therefore the persistent etc overlay cannot hide this change behind its old restrictive entry. The collector generated by initramfs runs after local-fs.target and writes `/boot/debug-logs`. Its existing fallback service also attempts `mount /boot`. When /boot is successfully mounted, review 009's USB fallback is not selected. On mount failure, the existing USB polling and eventual root-filesystem destination remain unchanged; this FAT mask does not grant permissions to those alternative destinations.

The early initramfs mount supplies no explicit umask and keeps its existing behavior. Actual loop reuse, shared-superblock mount options and autoclear across the retained early logger and systemd remain a Linux/device validation item from 005. The source-level fstab result is verified here; no successful runtime handover or user file-manager access is claimed.

The `SUPER_ONLY=1` return precedes userdata generation and fstab writes. Refreshing only super/boot therefore cannot change an installed userdata fstab. This change reaches newly converted userdata images; an existing installation would require a separately authorized configuration update or later full image workflow. No installed system was modified here.
