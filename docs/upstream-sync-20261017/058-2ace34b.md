## Slot switching: identity, backup and verified writes

The two public shell commands delegate to tablet-storage (Python3 is already required by tablet-firmware). Direct invocation also requires exact Elden; Gen3/EVO and similarly named boards are rejected. Mutation requires root; there is no automatic pkexec escalation. The slot operation requires a previously prepared dual boot, with stock Android retained on A and SteamOS started from B.

Validation uses findmnt JSON major:minor for the direct writable ext4 `/` filesystem (not source-string matching), resolves its sysfs block node, cross-checks actual block-device identity and rejects overlay/subdirectory roots. Its physical parent must report MMC device type **SD**, with a valid card CID; eMMC/MMC is rejected.

Boot partitions are enumerated from all sysfs partition uevents rather than ambiguous by-partlabel symlinks. Require unique boot_a/boot_b, distinct UUIDs/partition numbers, one common physical disk separate from the SD root, and an ancestor bound to `ufshcd-qcom`. USB disks with matching labels fail. GPT label/node/name/geometry must agree with sysfs; the table must pass sfdisk verification. Both slots must contain Android boot-image magic. Require B active and A inactive; unknown/conflicting slot state fails closed.

The target UFS disk and all children must have no mounts (checked by major:minor, covering aliases/binds), active block swap or holders. Loop backing block devices/filesystems are also checked because they need not appear in holders. Unresolved backing paths fail closed. The helper never unmounts or detaches anything belonging to another owner. The first-firmware unit must be inactive/failed before switching, avoiding its normal active extraction/reboot interval.

A shared nonblocking `/run/lock/tablet-gpt.lock` serializes this helper with the existing tablet-boot-ok helper; only that lock prefix was added to boot-ok. Both slot/growth commands use this lock. It does not serialize arbitrary external tools or manual firmware invocations.

Before mutation, save the textual table, JSON metadata and binary partition-table sectors to a unique root-only directory under `/var/lib/steamos-arm`, sync, and revalidate storage. Read the current table dump, change only the two boot entries' attributes and submit **one** sfdisk transaction. Source's two separate writes temporarily selected both A and B. The new transaction retains all other table fields and bits: A becomes active, retries7, not unbootable; B only loses active. Compare the entire normalized table against the expected result, sync and only then request a nonblocking reboot.

The [util-linux sfdisk documentation](https://kernel.googlesource.com/pub/scm/utils/util-linux/util-linux/+/refs/tags/v2.41.1/disk-utils/sfdisk.8.adoc) supports dump/sector backups, explicit device locking, attribute representation and the no-reread/no-tell-kernel controls used here. No `--force` is used. This is source-based utility-interface review, not execution of the shipped util-linux or firmware verification.

Failure retains the backup and does not request reboot. There is deliberately no blind whole-table rollback after a partially failed write or readback mismatch. If only the reboot request fails, A remains selected and the command returns failure; do not infer rollback. Android boot magic and slot bits do **not** certify stock ZUXOS, AVB acceptance or a complete healthy Android installation. Actual Qualcomm/Lenovo slot semantics remain inherited platform assumptions, not independently validated bootloader evidence.

## Partition growth: narrowly supported layout and retryable state

Source attempted any mmc root partition, forced sfdisk, ignored partx errors, and stamped success even if resize2fs failed. Reproduced the last error by executing the original source's final fragment with a failing mocked resize: exit0 and sd-grown were both observed.

The repair requires exact Elden, SD identity and writable direct ext4 root. Whole-device ext4 roots return without modifying a partition table or marking growth complete. Partitioned growth supports only a **single primary Linux root partition**, GPT or DOS, with matching kernel/table start and size. Multi-partition cards, eMMC, active swap (including swap files, conservatively), holders and backing loops are refused. It intentionally permits only this root filesystem's own mounts/binds, not other partitions/system storage.

Save backups and revalidate before growth. Preserve the exact start, use sfdisk -N with size+ and no force, and read back all metadata: only nonshrinking root size and GPT last-usable-LBA relocation may differ. Update only the selected kernel partition via partx; require blockdev's kernel size to match the table before resize2fs. Every command failure propagates. No completion marker until resize succeeds. Retain backups; never shrink a live filesystem or restore an old smaller partition table as automatic cleanup. A stale kernel partition size needs reboot/retry, not forced unmount.

The completion marker is atomically replaced JSON tied to CID, card capacity, disk ID, partition start/UUID/size and ext4 UUID. An old empty source marker or copied marker on another card cannot suppress validation. The unit's path-only condition was removed so the helper can validate identity. A failed run remains retryable; a whole-card raw filesystem is outside this partition-grow helper's scope.
