## Actual launch, identity and focus paths

Source adds `podman_cmdline --cgroups=split` to Lepton's mounting script, gated by nonempty KONKR_LEPTON_OVERLAY, and `Delegate=yes` to the nonroot user `konkr-android.service`. The existing service runs `konkr-apk daemon`, which patches Lepton, sets a shared SteamAppId/compat-data tree, preserves shared Android data, exports the chosen Wayland display and overlay list, and invokes Lepton. The setup service/desktop entries and Steam shortcuts call `konkr-apk run PACKAGE`; `store` calls the same function for com.android.vending. Other Steam Android games without the overlay keep their existing Podman options and identity.

[Podman's run documentation](https://docs.podman.io/en/latest/markdown/podman-run.1.html#cgroups-how) describes split as creating conmon and payload subgroups beneath the current cgroup and disallows an explicit cgroup-parent with it. Thus a payload under the delegated service is consistent with the existing Gamescope lookup. This is documentation plus source reasoning, not a measured target Podman/cgroup result. The installed Lepton mounting script/Podman command line and target systemd delegation were not available for live inspection; a future upstream cgroup-parent option could conflict.

Gamescope's `waylandy_type_surface_new` obtains the Wayland client's PID and first uses GetAppIdFromPid. If that finds no AppId, `get_container_appid` reads the client's host /proc/PID/cgroup. A Steam app scope supplies its numeric AppId directly; a path containing konkr-android.service marks the XDG window bKonkrAndroid. Identification is done when the surface is created, so a previously misidentified live surface is not repaired merely by updating these source files.

The launcher obtains the Steam reaper AppId and writes KONKR_ANDROID_APPID to the X root. The property handler updates a global ID and marks focus dirty. Every eligible shared Android XDG window receives that ID during focus enumeration; XDG IDs are also included in Steam's focusable-window report. Existing focus priority, overlay exclusions, Steam focus-control and per-window selection remain in charge. This change does not force focus directly or bypass those policies.

With no Steam reaper the launcher uses zero. With no DISPLAY the xprop helper is a no-op; Desktop Mode uses the existing KWin/Wayland behavior. An xprop failure is still best effort, not proof of successful assignment. A missing/unreadable cgroup, unsupported patch signature or preexisting nonzero process AppId can bypass the shared-service classification. No unrelated-window guessing/fallback was added.

All surfaces identified as the shared service follow one AppId, including multiple Android windows; there is no per-package surface identity. Existing XDG map/unmap flags, shared_ptr window snapshots, destroy unlinking/focus clearing and focus-dirty refresh remain unchanged. No new C++ pointer, listener or resource lifetime is introduced. Null-focus and discarded-feedback repairs from029/032 and output policy from046 are preserved byte-for-byte, along with their previously documented lifetime/runtime limitations.

## Findings and resolutions

1. **Shared patch-anchor idempotence.** Source inserts the cgroup block after the same `# namespaces` anchor as the existing LuaJIT rlimit block. After the first run the cgroup insertion separates that anchor from the rlimit block; on the next run each patch inserts again. Reproduced two copies of both options after two applications of the exact assigned source. Added a narrowly opted-in shared-anchor check for the complete inserted body. Both options now remain single across repeated application, including upgrading an already-patched049 installation. No change to the rlimit value, overlay gate or ordering semantics.
2. **Alternative property formats.** The source's new model/manufacturer-only signature matches inside the old brand/model/manufacturer patch's fallback, creating a nested second identity block and spurious warnings. Reproduced two identity blocks on the first source application to old syntax. Select exactly one known old/new property format, recognizing already-patched forms. Unknown identity syntax warns and remains untouched. With overlay enabled both versions emit the existing Google/Pixel5 identity; without it each emits exactly its original Valve properties, including the old brand only where originally present. This preserves the existing identity policy and does not establish Play Protect certification.
3. **Single owner of the shared window.** Previously two `run` processes could overwrite the same global AppId; either process exiting could clear the other's ID or stop the same package. Acquire one nonblocking per-user runtime-file flock before Android startup. Reject a second title with a clear message before touching Android or the property. `run` and `store` hold the lock until the launcher process exits. `idle-stop` now checks the same lock, replacing its command-line pgrep heuristic, so it cannot stop Android while a title is starting/running, including the `store` alias. Multiple windows within the shared Android session remain supported by existing Gamescope policy; simultaneous independent Steam title ownership is explicitly rejected.
4. **Release identity on launch errors and exit.** Install EXIT and signal cleanup after Android startup, before package/activity checks or AppId assignment. Normal exit, resolution failure, launch failure, shell failure and handled TERM/INT/HUP clear the property and schedule idle shutdown. Handled signals retain the existing package force-stop behavior. Separate the best-effort appops grant from `am start`, propagate a nonzero launch status and reject explicit Error/Exception text (Android can report an Activity failure with exit status zero). Failed launches no longer silently enter the running loop with an assigned AppId. Successful starts retain the existing package/home monitoring policy.
