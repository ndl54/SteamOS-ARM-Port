### High impact: unguarded writes and false success

The source removed root/partition and SoC checks, image checksum verification, backup readback verification and post-write verification. Its `dd` failures did not stop subsequent writes, and all three scripts could end with a success message after failure. Restore could begin writing slot A before discovering slot B had no usable backup.

Retained the flat layout but introduced `abl-safety.sh` as a **build-time template only**, concatenated into each shipped script. There is no runtime sourcing and no `$0` path discovery. Each shipped script sets `/system/bin:/system/xbin` before looking up Android tools. It checks readable/writable block partitions rather than trusting an `id` wrapper. It preserves the prior accepted SoC-model/platform alternatives and stops if properties/tools cannot be read; missing identity checks never authorize writing.

Both `abl_a` and `abl_b` must exist, resolve to distinct paths, be accessible, and report positive capacities through `blockdev --getsize64`. Flash snapshots the ELF into its temporary directory, compares it against the release hash **embedded in the generated script**, and verifies it fits both slots before backing up or writing. The distributed ELF checksum file is still emitted by the stager, but editing that sidecar cannot bypass the embedded expected digest.

Every partition write uses checked `dd`/`conv=fsync`, checked sync and a checked prefix readback/hash. Slot A is verified before starting B. Any failure returns nonzero, does not print success, and warns that a slot may have changed and that the device must not restart. Restore validates both full-size backup/checksum pairs, then snapshots and verifies both before writing either. Neither path changes the active slot or invokes reboot.

### High impact: preserve original backups

The source's standalone backup script unconditionally overwrote both backups. Its flash script also overwrote the surviving original when only one backup was missing or empty. Merely testing `-s` accepted truncated or corrupted backup files.

Both backup and flash now keep an existing verified pair. Any partial, legacy, wrong-size or checksum-mismatched pair stops the operation without overwriting it. New backups are read into temporary files, checked for exact partition size and hash equality with the original slot, then published with `.sha256` sidecars and synced before any partition write. A publication failure can leave a partial pair, which subsequent runs deliberately refuse to overwrite. Checksums provide corruption detection, not authenticity or proof of device identity.

Backups in the old `rocknix_abl/SMxxxx` subdirectory also stop the flat scripts. This avoids silently making a new backup of an already-modified ABL while ignoring the original saved in the old layout. Legacy backups are preserved; they require independent verification/recovery rather than automatically manufacturing a checksum and trusting them.

### Packaging and cleanup

Removed the source's newly introduced `rm -rf "$out"`: staging must not recursively delete a folder that could contain original backups, including former per-SoC subfolders. Staging still writes the flat ELF, checksum, README and three fully inlined scripts. Updated the release-file layout comment and README to describe the actual checks, four backup files, legacy-backup handling and failure/recovery behavior.

Runtime temporary directories are created beneath the fixed Android folder, with all paths quoted. EXIT/signal handling cleans only that run's temporary directory; backup files are outside it. Cleanup errors return nonzero, and successful-operation messages appear only after explicit cleanup succeeds. The existing tablet unmount/detach-before-delete protections are byte-preserved.

## Boundaries and remaining risks

No build scripts, compiler, kernel/Gamescope/InputPlumber/rootfs/image/package build, VM/container startup, mount, install, flash, reboot or deploy action was run. No adb/fastboot or hardware access occurred. All passing probes are synthetic host shell/file behavior; they do not establish Android root-tool, SELinux, storage/FUSE, signed-ABL acceptance, actual partition or hardware compatibility. The upstream claim about the root tool's failure mechanism remains unverified on-device. If Android cannot supply the system tools or properties, these scripts stop instead of disabling checks.

The shipped scripts remain one script per action after template concatenation; raw repository action bodies alone are not distributable scripts. Actual packaging remains deferred until the authorized post-109 build stage. Existing stale per-SoC directories are intentionally retained, not recursively removed. Legacy backups without checksums cannot be restored by these new scripts until an independently verified recovery procedure is used; do not delete originals or fabricate hashes to bypass the stop.

SoC/platform matching is the preexisting compatibility gate, not a new exact-board or device-serial allowlist. Users must use this device's own backups and the listed supported hardware. Backup hashes do not bind backups to a particular physical device and do not defend against malicious edits. Two-slot writes are not atomic: power loss, external concurrent modification or a hardware failure can leave partial state. Scripts must not run concurrently. A verified readback demonstrates byte equality only, not successful boot or secure-boot acceptance; no hardware-tested claim is made.
