The upstream change removes Pocket S2 from the service's model-name condition. Its rationale is that S2 shares the `SM8650-APS2` card but does not follow the FIT's WSA digital-volume curve, so forcing software volume to unity makes low volume too loud. This is the source author's hardware observation; this review did not reproduce speaker behavior on a device.

`apply-overlays.sh` copies the SM8650 overlay into the shared rootfs and makes the Python helper executable. It installs a vendor `default.target.wants/konkr-volume.service` link, so both desktop and Game Mode user sessions can activate the unit. The service retains its existing non-root user condition, model-file existence check, PipeWire/WirePlumber dependencies and restart policy. A manual systemd start uses the same condition. No other tracked launcher of the helper was found; direct execution of its installed path remains possible.

The helper constructs `Volume`, reads the digital maximum with `amixer`, resolves the speaker node with `pw-cli`, reads Steam/Pulse volume/mute with `pactl`, and writes PA/digital mixer values plus the node's `softVolumes`. Its event subscription and three-second periodic loop reapply the policy after node/route changes. Its generic speaker node name is not a board identity check. The existing `CARD = "0"` also cannot distinguish FIT from another board.

The shared root audio setup starts from sound.target/udev and sets the readiness marker used by WirePlumber's pre-start wait. The SM8650 branch initializes UCM and fixed amplifier/digital stages; it does not implement a recurring S2 volume curve. `53-konkr-audio.conf` leaves software mixing enabled. With this daemon excluded, S2 retains normal PipeWire software attenuation. The separate card-matched `55-konkr-speaker.conf` filter graph is unchanged and still covers APS2. `konkrctl speaker` toggles that filter and restarts WirePlumber; it does not launch the volume daemon. The rocker helper uses ordinary PipeWire/Pulse volume controls, not this hardware curve.

The shared `sm8550-audio-pipewire --watch` policy retains UCM-only routing for FIT/S2/EVO and does not set their initial volume. Report 011's exact NUL-separated `lenovo,tb321fu` early return remains in both shared audio helpers, including the setup helper's EXIT readiness marker. EVO's own UCM uses its WSA884x speaker lifecycle and MultiMedia2 speaker/DisplayPort selection, rather than the Odin MI2S fallback. These helpers and profiles are unchanged.
