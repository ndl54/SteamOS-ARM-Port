## Effective OPP change and correction to the explanation

The source's executable DTS properties are accepted unchanged. Its comment was corrected because the pinned tree contradicts several claims:

1. 903 MHz is **not the highest inherited OPP**. The shared board table already adds 903, 1000 and 1050 MHz without `opp-supported-hw` guards on those nodes. This change neither adds those higher frequencies nor caps the GPU at 903 MHz. Their availability/stability on a particular chip is not established by these text checks.
2. The shared 903 MHz node already has TURBO and `qcom,opp-acd-level = <0x882a5ffd>`. The old local append overwrote only the corner with TURBO_L1; omission of an ACD property did **not** delete the inherited ACD property. Thus this source restores the inherited corner and explicitly repeats the existing ACD value. It does not newly enable ACD on the normal pinned FIT tree.
3. No stock Android DT dump, per-chip characterization, measured voltage/power/temperature or benchmark run was supplied/produced. The author's “factory”, “about 1 W”, “5C” and universal Snapdragon claims are not independently verified. The revised comment describes the pinned ROCKNIX agreement and explicitly leaves hardware verification open.

`opp-hz` is a 64-bit frequency in Hz; 903000000 means 903 MHz. `opp-level` is an abstract RPMh performance/corner value, **not microvolts**. The constants come through `dt-bindings/power/qcom-rpmpd.h` to `qcom,rpmhpd.h`, not the regulator-mode header. `opp-peak-kBps` is peak bandwidth in kilobytes/second. [The Adreno OPP binding](https://github.com/gregkh/linux/blob/v7.2.8/Documentation/devicetree/bindings/opp/opp-v2-qcom-adreno.yaml) defines ACD as a unitless encoded characterization value sent to the GMU; it is neither a voltage literal nor a frequency.

Read the pinned/reconstructed a6xx_gmu.c and a6xx_hfi.c: the GMU builds frequencies in ascending Hz order with an initial off entry, maps `dev_pm_opp_get_level()` through command-database ARC tables to primary/secondary votes, and sends HFI frequencies in kHz (`/1000`). It reads ACD from each OPP's OF node, sets the corresponding level bit, passes the value to firmware, and notifies AOSS through QMP. Missing/invalid QMP when ACD is needed remains an error; the existing disable_acd override remains unchanged. Actual voltage depends on firmware/command database/hardware, so no numeric voltage reduction can be derived here.

The reconstructed table has 14 nonzero OPPs, 15 GMU entries including off, 14 ACD values, and monotonically increasing corner values after this change. This fits the inspected 32-entry GPU frequency/ACD storage. The GPU devfreq code derives its table from OPPs; devfreq cooling derives frequency limits from that table. This change does not alter the frequency count or cooling-state ordering. These are source-level checks, not runtime enumeration.

## Thermal preservation and pre-existing issue requiring follow-up

All eight GPU 95 C passive throttling trips and their `<&gpu THERMAL_NO_LIMIT THERMAL_NO_LIMIT>` maps remain unchanged by 075, as do GPU 110 C hot trips, cooling registration, TSENS handling and fan driver/configuration. No cooling map was removed and no thermal limit was raised by this source. Neither lower requested corner nor ACD proves safe temperatures or stability.

**A pre-existing thermal defect was found in the pinned ROCKNIX common DTS:** for each of `gpu0_trips` through `gpu7_trips`, the base Linux node `trip-point2` is 115 C/critical, but the shared board file reuses the *same node name* for its first 40 C/passive “fan” trip. Normal DTS merging replaces its properties; a new label does not create a distinct sibling. Therefore it is incorrect to claim that the base GPU 115 C critical trips survive this board include. All eight collisions were confirmed against the targeted patched SM8650 source. The shared file has no cooling maps connecting its newly labelled GPU fan trips; a label alone is not an active fan binding.

This defect predates 075 and affects the shared FIT/S2 policy. It is recorded for the final global validation/repair scope; this narrowly assigned corner change does not invent a replacement fan/shutdown policy or edit other boards. Existing GPU passive throttling and other thermal zones are not proof of equivalent critical shutdown protection. Do not treat the resulting configuration as hardware-safe on the basis of this integration.
