## Necessary resolutions beyond the source

1. **Malformed UCM commands:** 150 `cset` lines across canonical/duplicated entrypoint files lacked closing double quotes. Closed the strings in all affected files, preserving mixer names/values and aliases. Without this, the command strings consume following configuration text. All 26 SM8250 UCM files now pass the focused lexical command check and all local File references resolve. This is not an alsa-lib/UCM hardware-control validation; generic codec/lib includes come from the target rootfs.
2. **Persistent `/etc` profile staging:** source only copied/removed the base-layer files. An existing upper-layer InputPlumber profile could shadow the new one, and switching a reused rootfs to another SoC left SM8250 profiles in the upper. The installer now copies/removes only the overlay's named files in both base and an already existing `/var/lib/overlays/etc/upper`, stripping `etc/` for the latter. It creates no upper on a fresh root, leaves unrelated/custom files and REDMAGIC's sm8250 UCM entry alone, and retains existing SOC behavior outside the new named payloads. The isolated source block reproduces both stale-upper failures.
3. **Inherited Odin audio fallback:** the installed shared `sm8550-audio-pipewire` treated all new SM8250 models as non-UCM and selected pro-audio plus Odin MI2S routes. Added exact `qcom,sm8250` selection of the existing UCM-only branch. The installed SM8650-overlay `sm8550-audio-setup` now exits early for the same token, with its existing ready-marker EXIT trap, avoiding the irrelevant 20-second card-name wait and Odin setup. The rest of both helpers is byte-identical to starting main; EVO/FIT/Odin behavior is unchanged. Mocks cover local and DP selection, not real PipeWire profiles or sound.
4. **Missing SLPI payload:** the inherited DTS enable SLPI at `qcom/sm8250/slpi.mbn`, but the source's firmware list omitted it. [ROCKNIX's pinned kernel-firmware recipe](https://github.com/ROCKNIX/distribution/blob/c445081a59518f37d9776e5412dd7b14910696f7/projects/ROCKNIX/packages/linux-firmware/kernel-firmware/package.mk) explicitly moves RB5 `slpi*` into `qcom/sm8250`. Added `slpi.mbn`, `slpir.jsn` and `slpius.jsn` from `qcom/sm8250/Thundercomm/RB5` to that destination, verified against [linux-firmware tag 20260916 directory metadata](https://gitlab.com/kernel-firmware/linux-firmware/-/tree/20260916/qcom/sm8250/Thundercomm/RB5). No firmware binary/device was run. Extra-firmware metadata confirms the separate Thor ADSP/amp and PocketMax MCU payloads; the inherited Thor DTS still requests generic ADSP, now explicitly noted rather than claiming the special blob is selected.
5. **Incomplete 60 Hz session cap:** source set PANEL_RATES=60 but its subsequent conditional only exported lists containing a comma, and it retained a stale GAMESCOPE_REFRESH/STEAM_DISPLAY_REFRESH_LIMITS=120 override. The exact two non-Visionox models now explicitly set initial REFRESH_HZ and exported limits to 60; the flag is reset before board selection. The regression reproduces `120|60|60,120` from source and gets `60|60|60` after repair. Six other/missing/lookalike models retain their previous results. This constrains the session configuration; it is not a physical panel validation or a kernel prohibition on manual modesetting.
