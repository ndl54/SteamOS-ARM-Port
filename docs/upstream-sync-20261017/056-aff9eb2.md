## Accepted integration and semantic repairs

Source adds a Python calibration helper, its public executable symlink, a boot restore unit, installation in the shared and SM8750 overlays, and user instructions. Both overlay installation blocks are retained unchanged. The new userspace helper is the first repository consumer of the calibration attributes introduced in source055.

### Measure the intended display and actual frame count

The original helper selected the first card/pipe accepting WAIT_VBLANK. That can be an external display while the helper writes the built-in panel's attributes. It also inferred 60/120 from measured Hz, allowing an unrelated or incorrectly measured stream to choose the wrong attribute.

The helper now requires the unique DSI connector on a supported board, reads its connector ID, obtains its current encoder/CRTC through DRM GETCONNECTOR/GETENCODER, and maps the CRTC ID to its GETRESOURCES array index. GETCRTC supplies the nominal mode, which must be 60 or 120 Hz. It checks the connector route and full mode snapshot before and after every measurement. Disabled, ambiguous, unsupported or changed routes fail rather than choosing a different pipe. GETCONNECTOR requests one temporary mode element to avoid triggering a forced probe. No modeset ioctl is used. Descriptors are closed on success and failure.

WAIT_VBLANK returns a sequence and monotonic timestamp. The original helper counted ioctl calls; the process can miss multiple frames between calls. Repaired measurement sums unsigned 32-bit sequence differences, including wrap, and divides by timestamp elapsed time. Nonadvancing/reversed timestamps, implausible sequence jumps and rates more than 5 Hz from the selected nominal rate fail. Timestamp arithmetic uses integer microseconds until the final rate division.

The ioctl sizes, field offsets, sequence semantics and mode conversion were reviewed against Linux v7.2 `include/uapi/drm/{drm,drm_mode}.h`, `drivers/gpu/drm/{drm_crtc,drm_connector,drm_modes}.c`, and the pinned v7.2.8 drm_vblank.c used in report055. Linux arm64 is the intended runtime. This is UAPI/source review and mocked ioctl coverage, not real DRM execution.

### Restrict calibration and persisted input to the intended hardware

The original helper selected any MIPI-DSI device with frame_len_60, and boot apply turned every JSON key into a path without validating it. It converted arbitrary values through int(), could silently discard unreadable configuration and could crash on some malformed values.

The helper now allows only these exact board/panel pairs:

| Board compatible | Panel compatible | 60 Hz range | 120 Hz range |
| --- | --- | --- | --- |
| `retroidpocket,rp6` | `vtdr6130,rp6` | 0x76C–0x834 | 0x10–0x80 |
| `ayn,odin3` | `chipone,icna3520` | 0x770–0x838 | 0x10–0x80 |

The bounds are from the resulting driver stores, not inferred timing values. RP6 TOP-DPAD inherits the RP6 compatible. Nova, Thor, Pocket FIT Elite and EVO are not automatically included because they share a SoC or driver family. Both attributes must exist and exactly one matching panel must be found.

Saved JSON contains board identity, panel compatible and a `values` mapping. Only frame_len_60/frame_len_120 with exact integer types (excluding booleans) inside the matching bounds are accepted, before any write. Missing files mean no saved calibration; malformed, unreadable, other-board and old unbound files produce explicit errors. The tips explain moving an old/mismatched file aside and recalibrating. The file is tied to board/panel **types**, not a panel serial number, so copying it to another unit of the same model is not an independent calibration of that unit.

### Converge within bounds, serialize writers and recover honestly

Fixed 4/8-unit steps can oscillate around a narrow acceptable interval without ever reaching an available integer solution. Replaced that search with a bounded integer binary search under the same longer-frame/lower-rate assumption as the source. It begins at the current value, stays within the driver bounds, runs at most ten iterations, and requires the final three-second sample to satisfy the same tolerance (0–0.05 Hz above 60, or 0–0.2 Hz above 120). Failure to converge does not save a best-effort value. Documentation describes this tolerance and possible failure instead of promising exact Hz or a fixed 20-second completion.

A nonblocking flock serializes helper calibration and boot apply. Saved files use a unique temporary file, flush/fsync and atomic replacement, with temporary cleanup on failure. Configuration errors are checked before calibration writes. Transfer failures, final measurement errors, save failures, KeyboardInterrupt and handled SIGTERM/SIGHUP attempt to restore the starting value. The changed flag is set **before** the write because source055's driver caches the desired value before a possibly failing transfer. A failed restore explicitly reports uncertain panel state instead of falsely saying the old value was kept. Kernel mutexes remain necessary for other writers and lifecycle/backlight operations.

Boot apply retains the saved-file condition and ordering after modules-load/before display-manager. Modules-load alone cannot guarantee deferred probe completion, so apply waits up to ten seconds for the supported panel; the service has TimeoutStartSec=20. It reports a missing panel or transfer errors with a failing exit rather than silently succeeding. It attempts both validated saved rates, reports partial failure, and does not claim transactional hardware rollback. Unsupported boards return without panel access.
