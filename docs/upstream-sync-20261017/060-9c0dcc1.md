## Findings and resolutions

1. **Constrain the exception to cache files.** Upstream's substring match also exempted unrelated application data under `opt/.../pacmandb/sync`, arbitrary JSON in `__pycache__`, cache directory names and configuration paths. Limit Python candidates to `.pyc` directly inside `__pycache__` under managed usr/opt or the two bundled plugin trees. Limit pacman candidates to direct `.db`, `.files`, `.db.sig` and `.files.sig` files in `root/usr/lib/holo/pacmandb/sync`. Reject noncanonical/absolute/traversal keys in the predicate. `/etc`, overlay configuration, arbitrary HOME, pacman local package records and normal managed artifacts receive no new exemption. Unknown cache naming/layout conservatively keeps the normal missing-blob/full-fallback behavior.
2. **Do not delete through links or recursively delete a type mismatch.** Before exempting a missing-blob cache, lstat each existing parent from rootview/HOME and require real directories; require the existing leaf to be a regular file. Missing paths are allowed, but a parent symlink, leaf symlink, directory-as-file or special type raises a nonretryable ValueError. No resolve/dereference-based deletion is introduced. Upstream could schedule a directory for recursive deletion or plan deletion through a symlink parent. Ordinary-file sentinel tests reproduce and prevent both cases. These are staging guards, not a complete race-proof rewrite of every filesystem operation.
3. **Do not falsely record retained cache contents as installed target bytes.** Upstream retained a drifted pacman database and then recorded the signed target hash with that live file's size/mtime. A subsequent plan could incorrectly trust it as matching. Record skipped keys in the transaction plan and exclude them from apply2's generated inventory. The original signed target stays unchanged. Recreated pyc files are likewise not assigned an unverified release hash. The next plan rehashes these files; installed release version still advances only through the existing apply/commit flow.
4. **Preserve backup and rollback semantics.** Existing pyc deletions remain in plan_keys and are backed up; retained databases are not changed. The 052 installed-inventory backup/restore and legacy fallback are byte-identical. Regression exercises real temporary-file plan/backup/apply/restore: drifted pyc returns after rollback, pacman bytes stay untouched, and previous inventory/version is restored exactly. PRETTY_NAME-only labeling, pending suppression and the 053 name remain unchanged.

The new predicate is an omission exception, not a promise that every cache is globally unmanaged. Existing generic deletion of live paths absent from the signed target remains unchanged. It does not preserve arbitrary user/custom files placed inside managed directories or ensure an official package carries fork-specific files.
