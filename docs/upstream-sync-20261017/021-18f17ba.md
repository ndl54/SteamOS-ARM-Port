## Runtime, opt-in and destinations

The common builder packages bootdebug in the initramfs. Init copies it into the real root and generates the Type=simple service after local-fs.target. The common and SM8750 overlay installers also install it with the fallback file-trigger service; generated-unit suppression remains intact. Upload therefore runs under the real root's shell and utilities after switch_root, not inside early BusyBox. Python 3 already has rootfs consumers including the desktop layout helper; the uploader checks curl/Python/journalctl/tar availability, but final-image dependencies remain unverified.

**Uploading requires both exact, whitespace-delimited kernel tokens:**

```text
steamos.session=plasma steamos.logupload=1
```

The second token is a deliberate integration repair: selecting Desktop Mode is not consent to publish logs. Neither Desktop alone, a debug/debug.txt file, `steamos.debug=1`, nor screenlog alone sends data or starts the uploader. Upload-token lookalikes do not activate it. The exact upload token also enables the normal local collector through both initramfs and fallback activation paths; without the Desktop token it only enables local diagnostics. No recipe or default cmdline is changed to enable uploading. This includes the existing Elden forced-debug path.

The original Desktop override creation/removal, including pending late-overlay cleanup from 020, is unchanged. An updated common initramfs is still needed to implement Desktop boot selection; the fallback collector alone cannot add that session feature. A kernel with a forced command line must actually deliver both tokens. Combining screenlog with upload retains the explicitly requested graphical-session stop; it can interrupt the Desktop UI used to connect to Wi-Fi.

Network destinations remain those in the assigned source: HEAD readiness requests to `https://gofile.io`, then one multipart `file` POST to `https://upload.gofile.io/uploadfile`. There is no fallback upload provider. Curl retains TLS verification, does not follow redirects, and disables curlrc with the first `-q` option so a local configuration cannot silently add redirects/options. Network/proxy environment and the server's actual behavior are outside these local checks. No request to either service was made during this review.

Readiness is at most 120 attempts, each with a ten-second curl limit, with 119 ten-second sleeps: approximately 40 minutes worst case plus preparation/overhead; it is not a Wi-Fi-specific detector or a strict 20-minute wall-clock bound. The POST has a 300-second limit and no automatic POST retry. The Desktop status file explains wait expiry and upload failure. A failed response can follow a server-side receipt, so it explicitly does not claim that no data was sent after a POST.

The result is `/home/steamos/Desktop/LOG-LINK.txt`. Writes and directory creation run as `steamos`, preventing root from following user-controlled Desktop/status symlinks as a privileged writer. This literal Desktop path and user remain source/image assumptions; localized/custom XDG Desktop paths are not detected. Each new opted-in attempt replaces the status; ordinary boots do not clear a prior link.

## Data selection and repairs

1. **Exact separate consent.** Replaced the source's permissive `grep -qw 'steamos.session=plasma'` and Desktop-implies-upload behavior with the two exact gates above. The source regex also accepts lookalikes such as `steamosXsession=plasma`; reproduced locally.

2. **Select an evidenced prior boot.** Read the boot list once, inspect offsets -1 through -6 newest first, and require the source's `gamescope version` marker in UID 1000 messages. Pin the 32-hex boot ID for subsequent journal queries. If none matches, or queries fail, stop without networking; do not silently default to boot -1. The Gamescope producer is `src/Utils/Version.cpp`, using the process name plus `version`; the marker remains a heuristic, including possible nested Gamescope usage, not proof of a particular systemd session. Missing/rotated logs or different UID/log routing may prevent selection. Every journal query is noninteractive.

3. **Explicit archive contents.** Include full system and UID-1000 journal exports from the selected prior boot, the current boot's full journal, boot list with the selected ID, current Steam logs, optional current bootstrap log and directory listings. Steam logs are not historical snapshots tied to the chosen boot. The archive does not add BOOT/USB collector files, early bootlog, KMS dump, pstore, devcoredump, EVO audio/sleep snapshots or arbitrary home files. The full system journals can still contain unrelated services' messages, personal identifiers or secrets; there is no redaction promise. Opting in sends these unredacted contents to a third-party host. The returned link is presented as shareable only as intended; service retention/access/deletion policies were not verified.

4. **Never send a stale or failed archive.** Use a unique private `/run/steamos-arm-upload.XXXXXX` directory with umask 077; data, archive and response live under it. Abort on journal-list/export, temporary-directory or tar failure before networking. The source uploads the fixed `/run/steamos-arm-logs.tgz` even when tar fails, potentially sending an old/partial archive. That behavior and leaked source temporary data were reproduced with mocks. Integrated EXIT/HUP/INT/TERM traps remove only this attempt's private directory. Normal success, failures and TERM cleanup passed. SIGKILL/power loss and kernel I/O stalls remain outside shell-trap guarantees; `/run` is transient on the target. Optional Steam copy failures remain tolerated; symlinks are preserved rather than recursively dereferenced, and tar does not follow them.

5. **Check the response and the transport separately.** Do not pipe curl errors through a permissive sed expression. Require curl success, valid JSON with status `ok`, and a `data.downloadPage` string matching `https://gofile.io/d/` plus an alphanumeric/underscore/hyphen identifier. JSON whitespace and escaped slashes work; malformed, error-status or different-host responses fail visibly. This is the expected source contract, not verified compatibility with the current public API. Provider/API changes, requirements for authentication, limits or a different URL shape can require a later change.

6. **Keep the service alive for the upload.** Like the existing reporter, the background upload must not be killed when the Type=simple service's main process exits after a collector failure. When either worker exists, execute the unchanged collector in its own subshell, let its owned-USB exit cleanup finish, then wait for the upload and screen workers. The actual parent tail was exercised after a mock collector exits. No KillMode override, detached daemon or change to default service cgroup ownership was introduced.
