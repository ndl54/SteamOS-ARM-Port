### Installed layout is not an unfinished-install detector

Upstream treats the three trailing names ROCKNIX/STORAGE/HOME as `installed`, regardless of filesystem contents or deployment completion. There is no trusted completion journal. A working installation therefore also qualifies. Kept the observation but labeled the action **Erase and install again**, with explicit erasure of internal games, saves and backups; this is not an update or data-preserving recovery. Partition sizes stay unchanged on retry. New installs retain source081's 16 GiB Android minimum; old smaller userdata is not expanded/erased by retry.

The original probe computes fresh-install size limits from remaining userdata, so installed layouts can have a maximum below the minimum. The GUI now bounds its disabled size control and displays preserved sizes for reinstall. Refresh immediately clears cached authority and disables install, including on probe/thread failure. A rejected retry exposes the check's reason. A fresh install continues to use the existing fresh sizing flow.

It only checked the three destination nodes for mounts, leaving swap, holders, loop backing and stale kernel partitions unprotected. Names alone did not establish a physical UFS target or an SD source. Added read-only `ufs-resume-check.py`, used by the probe and independently by the root installer before planning and again immediately before formatting:

- Canonical whole `/dev/sd*` target, distinct from source, with Qualcomm UFS driver ancestry, writable block nodes, matching `/dev`/sysfs major:minor and physical partition parents/numbers.

### Passwordless scope deliberately narrowed

**The upstream passwordless write grant is not retained.** Its exact-path policy covers all arguments of `install-masios-to-internal.sh`, including `--disk`, fresh partitioning, metadata erasure and tablet boot writes; policy path matching does not limit it to the GUI's retry arguments. The inherited fresh path still selects target by labels, permits explicit disk input, has broad SoC gating and discovers metadata across LUNs; tablet boot discovery uses global partition labels. Hardening the retry path does not make those other operations safe to grant without administrator authentication.

The two explicit action paths are installed, with `allow_any=no` and `allow_inactive=no`. The read-only probe alone uses `allow_active=yes`; installer uses `auth_admin` without authorization caching. Direct script argv replaces `bash SCRIPT`, matching policy paths; no generic interpreter authorization or shell interpolation was added. README/UI state that installation still requires a password/admin authentication. Stock SteamOS without a configured password cannot use the write action until configured. That is an intentional source divergence, not a claim that the original passwordless-install feature is fully delivered.

Because `cp -a` preserves checkout ownership, packaging now explicitly assigns root ownership and removes group/other write bits from the helper tree; the installed policy is root-owned mode0644. Otherwise a writable passwordless probe/helper could become arbitrary root code. The current source tree contains no symlinks. These are source-level staging checks; effective installed parent-directory ownership, polkit rules and session classification still require later image validation.
