## Findings and resolutions

1. **Recursive upstream ADB wrapper.** Upstream discovers native ADB as the literal `adb`, then defines `adb() { "$ADB" "$@"; }`. Bash resolves that name back to the function, causing recursion. Resolve the executable before defining the wrapper, require an executable file, and invoke it with `command`. Honor the explicit `ADB` environment value as one executable path (including spaces/Unicode), otherwise prefer native adb then adb.exe. Windows suffix detection accepts mixed case. No eval, splitting an executable path into arguments, or global shell PATH mutation.

2. **Incomplete conversion after semantic merge.** Upstream changes four pushes;059 has two additional pushes for `storage.sh` and generated `card.sh`. All six now use one adapter. Every local source is converted through `wslpath -w` for Windows ADB, while the Android destination stays unchanged. Source paths are absolute and individually quoted. Each conversion is a separate checked assignment, so converter failure or empty output cannot silently become an empty/partial adb argument. Require wslpath for Windows ADB and preflight static release/work paths before any remote mutation. Windows work files stay in a unique `.work.*` beside the release; native hosts retain mktemp's normal temporary location. WSL network/UNC and drive access are still runtime validation boundaries.

3. **CRLF and failure handling.** Normalize only textual serial/state/property/root output, retaining pipefail and checking command status before accepting its content. The old inline get-state/root comparisons could accept convincing stdout despite nonzero ADB status; combined model/property command substitutions could mask an earlier failure. Read model and device independently and retain exact TB323FU-or-baldur property gating plus the unchanged Android exact-DT gate. Binary `exec-out` output is never CR-stripped or routed through the text adapter, preserving boot images and firmware tar bytes. Push and shell errors propagate; EXIT cleanup preserves the original nonzero exit status and reports a failed lock removal without converting failure to success.

4. **Stable target selection.** Resolve get-serialno once, respecting inherited ANDROID_SERIAL, and reject errors, unknown/empty/whitespace serials. Subsequent state checks, properties, pushes, exec-out, su commands, lock cleanup and optional switch use the explicit `-s` serial. Without a supplied serial, ambiguous ADB selection must fail. No automatic selection of the first device, reconnect loop or retargeting on disappearance. This binds an ADB serial, not cryptographic physical-device identity.

5. **Apostrophe in Windows release path.** Moving work next to a user-selected release makes the existing interpolated Python string in `shutil.make_archive('$W/...')` unsafe for apostrophes. Pass the archive base as `sys.argv[1]`; it remains data rather than Python source. The source now accepts both `--switch` and `-switch`, preserving default stage-only behavior and rejecting unknown/extra arguments. No new consent bypass or automatic reboot was introduced.
