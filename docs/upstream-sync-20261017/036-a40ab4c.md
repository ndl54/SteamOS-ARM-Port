## Semantic resolutions

### USB ownership, storage and retry

The source's shared unbind loop affected every board with this driver, tested only `/dev/sd*` mount text, truncated its state at each pre and deleted it even on failed bind. Ported its fresh-probe intent into one Python helper under the EVO overlay, invoked by the actual EVO path and board-gated common xhci functions.

The helper is exact-board gated before state/device access, locks its root-owned runtime journal, records intent atomically before detach and preserves it across failed post or repeated pre. It only binds recorded devices; an already bound device is left alone, a device belonging to another driver is never stolen, and missing devices stay pending. Bind is checked against the actual driver symlink, with three bounded-count attempts and 0.1-second inter-attempt delays. A later pre/post retries pending recovery. Invalid journal names and storage-inspection failures fail closed.

Storage policy is deliberately more conservative than upstream: **any** block device/partition or USB mass-storage interface under the Renesas PCI host prevents detach, even if currently unmounted. This protects swap, mapper/holders, UUID mounts and other mount namespaces without depending on mount-text names, and catches mass-storage interfaces before a block disk appears. UFS remains bound on EVO for SD and internal boots; common direct UFS calls now enforce the same exact-board exemption. Other-board UFS behavior is unchanged. No global PCI remove/rescan, module reload or storage unbind was introduced.
