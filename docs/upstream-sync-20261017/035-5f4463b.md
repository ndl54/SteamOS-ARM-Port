## Findings and resolutions

1. **Mode eligibility must precede ranking.** The source only checks count_modes when comparing different screen types. A preferred external with zero modes can beat another usable external, and a connector with only the blocklisted 4096x2160 modes passes count_modes but later fails find_mode. Its cross-type rule can also produce a cycle: usable external beats internal, internal beats empty external, and preferred empty external beats usable external. Filter every candidate through the existing find_mode(..., 0, 0, 0) before ranking. This uses the same blocklist as final mode selection and makes the external-first comparison consistent among eligible outputs. These are source/control-flow counterexamples, not executed C++ reproductions.
2. **Reject an unavailable route before mutating selection.** Check that the CRTC selected by the existing find_crtc_for_connector has a routable primary plane in the currently owned resources. Otherwise keep considering the internal panel/another external. This matters when a lease has removed a CRTC/plane. It is a static resource check, not an atomic KMS test, and does not search alternative CRTCs beyond the existing chooser's first result or guarantee bandwidth/format/link feasibility. Allocation and atomic failures remain separate limitations.
3. **Force-internal now wins over legacy allow variables.** The source retained an earlier GAMESCOPE_ALLOW_HDMI/GAMESCOPE_ALLOW_EXTERNAL bypass ahead of g_bForceInternal, contradicting its new explicit keep-panel promise and Steam's switch. External output is now allowed by default, so these allow variables are redundant; they cannot defeat explicit internal forcing. Removed that bypass and corrected the old misleading “DSI present” skip log. This is an intentional precedence correction.
4. **Do not retain an ineligible current output.** Previously, no best candidate plus a current connector returned success and retained it, including an external just excluded by Steam's internal-only policy. Retain only a current connector that still wins eligibility/ranking; otherwise use the existing headless unset path. This changes logical selection, not the existing physical power-off/atomic teardown semantics described below.
5. **Keep failed internal-backlight shader dimming off a monitor.** update_color_mgmt previously copied GetSoftwareBacklightGain unconditionally. When the panel backlight write fails, that gain can be below one; docking would then dim an unrelated external monitor. Apply this fallback gain only to an internal current connector and use unity for external output. Internal hardware writes, normalized brightness state, floor/curve, EVO profile and HDR brightness policy are unchanged. The existing brightness-atom handler can transiently assign the pending gain, but paint calls update_color_mgmt before constructing the frame/LUT state, where the connector-specific value is restored.

## Hotplug, mode, rotation and ownership trace

The KMS-device change callback marks DirtyState and nudges the compositor. PollState re-enumerates connectors/properties, removes disappeared map entries and clears the current pointer when necessary, then runs selection. A newly connected eligible monitor takes over; a disconnected/removed or newly mode-less monitor falls back to a qualifying internal panel or another eligible external. Same selected connector is retained unless forced or its EDID changes. A no-output case uses the existing virtual connector. refresh_state/setup errors are not comprehensively propagated by drm_poll_state; this integration does not certify that error path.

After choosing a connector, drm_set_connector chooses its CRTC/primary plane, recreates liftoff output/layers, clears old current/pending mode IDs, and requests a modeset. Mode choice remains explicit preferred dimensions/refresh, then saved external mode keyed by description, then the first accepted sorted mode. Invalid saved/preferred choices fall back to the latter. The session starts from internal logical dimensions and 60-Hz nested refresh; these are not promises of the monitor's native resolution or refresh. drm_set_mode derives actual output geometry/refresh from the chosen mode and resets dynamic refresh and output rotation. A 90/270 internal panel transposes dimensions; returning from a normal external re-applies the panel's own orientation. --force-orientation is internal-only. Default shader rotation and the opt-in KMS rotation/retry policy are unchanged.

The compositor polls before updating mode/EDID atoms, updates Steam's root Xwayland mode, and recreates Vulkan output images when dimensions, refresh, rotation or HDR state change. External modes are exposed separately to Steam. Internal refresh-limit environment and Mangoapp font scale remain startup values; this change does not add per-monitor live scaling. The existing fake physical size also applies externally. These UI/DPI limitations remain explicit.

For a real modeset, drm_prepare unlinks foreign planes, disconnects owned connectors/CRTCs, clears their old color/VRR state and attaches the selected connector/CRTC with its mode and properties. Leased objects are removed from the owned vectors/map and stay outside that transaction. Framebuffer references flow request -> queued -> visible on the matching page-flip event. Commit advances current properties on success, restores queued refs/counters on EBUSY/EACCES, and retains fatal handling for other atomic errors. Its pending-flip wait and event/CRTC matching are unchanged. No new lifetime shortcut or null guard is offered as a DRM/wake repair.

When no eligible output remains, drm_unset_connector destroys liftoff selection and uses the virtual mode. drm_prepare already returns EACCES without a connector, and Present returns before Commit. Thus this path does not dereference Commit's real-connector feedback pointer. It also does **not** issue a new disabling atomic commit: a physically connected but policy-excluded old output may retain its last scanout until a later modeset. Framebuffer refs are not prematurely dropped to fake a successful detach. Physical blanking/headless ownership needs separate lifecycle work and runtime evidence.

## EVO, HDR, brightness, touch and prior work

The exact EVO compatible gate still supplies GAMESCOPE_INTERNAL_DEVICE_ID and conditionally enables HDR only for a supporting binary. ParseEDID supplies that device ID only for internal connectors. The ICNA3512 profile additionally requires internal + no physical EDID, so its estimated P3/gamma22 HDR characteristics do not get stamped onto an external monitor. External HDR uses that connector's capabilities/metadata. Backlight-LUT dimming remains gated by the active connector's HDR profile; the additional software fallback isolation is described above. Monitor DDC brightness is not implemented by this change.

EVO internal refresh switching still refuses unlisted rates rather than synthesizing vendor timings. Its kernel modes, rotation, brightness commands and profile bytes are unchanged. External dynamic refresh remains disabled by default unless the existing explicit configuration/profile enables it. The general external synthetic-mode path and EDID/bandwidth validation are not redesigned here.

Touch still associates I2C devices with an internal connector and USB devices with an external connector, applies that connector's orientation, and maps into current output dimensions. Therefore the handheld touchscreen can continue to control the active external output; no touch injection or physical calibration was tested. Dual-screen ignore rules and leasing are unchanged. Existing cached raw touch connector pointers are not invalidated when DRM removes a connector map entry: removal of a USB/MST output while its touch input survives can leave a stale association. Broader connector publication/lifetime synchronization and touch re-association remain open; this selection repair does not claim to fix them.

All code outside the reviewed selection regions in DRMBackend is byte-preserved, including mode/refresh/orientation, EDID/profile lookup, formats, LUTs, prepare/present/commit/page-flip, lease and teardown. steamcompmgr changes only the fallback gain assignment. Reports015/022/029/032 retain exact Elden 8-bit/linear scanout handling, PipeWire deadline/atomic node/init cleanup, locale-safe startup Mangoapp scaling, feedback discard helper and null-keyboard-focus clear. Their pending feedback, detached capture and wake/lifetime limitations remain. Source034 Desktop migration and its config-preservation tests are untouched. All other tracked product paths remain unchanged, including UCM/audio, bound-UFS EVO sleep, Wi-Fi restore/scan, LEDs, exact-board gating, collector and USB/KMS work. The upstream HDMI/DP audio statement is not new evidence of working audio routing or a reason to modify UCM.
