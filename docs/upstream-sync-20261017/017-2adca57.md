## Review and runtime trace

Read the protocol and reports 009, 011 and 016. Reviewed the complete source delta, the current tablet installer, overlay install path, shared system-disk rules, bootdebug ownership behavior, tablet DT/kernel recipe and USB patch boundaries, EVO kernel inheritance and existing isolation tests.

`apply-overlays.sh` runs `install-tb321fu.sh` when any supplied kernel output basename ends in `-tb321fu-steamos`. The installer adds `90-steamos-arm-tb321fu-usb-storage.rules` under `/usr/lib/udev/rules.d`. A combined rootfs can run on other boards, so runtime board gating matters even though installation is selected by kernel output. Normal image boot/add/change events apply the rules; this commit does not reload a running host's udev database.

The rule sets `UDISKS_CAN_POWER_OFF=0` on USB block disks and `UDISKS_IGNORE=1` on block devices whose `ID_PATH` contains `ufs`. The latter covers disks and partitions. Existing `98-steamos-arm-system-disk.rules`, separately installed later by apply-overlays, already hides `sd*` UFS ancestry through `DEVPATH=="*.ufshc/*"` and protects the system disk. The new tablet UFS rule is complementary/redundant for those usual paths, not the first protection in this fork. Neither rule prevents privileged/manual access or fstab mounting.

The [UDisks manual](https://storaged.org/doc/udisks2-api/2.11.0/udisks.8.html) documents both overrides. Inspected [UDisks 2.10.1 drive implementation](https://github.com/storaged-project/udisks/blob/udisks-2.10.1/src/udiskslinuxdrive.c): USB ancestry normally sets CanPowerOff, then the udev override replaces it. PowerOff checks drive/sibling use, syncs block devices, attempts SCSI cache/stop commands, then writes the USB device's sysfs `remove` attribute. Its inspected handler does not itself enforce the CanPowerOff hint, so this is not a prohibition against explicit D-Bus/manual power-off requests. [Block implementation](https://github.com/storaged-project/udisks/blob/udisks-2.10.1/src/udiskslinuxblock.c) maps UDISKS_IGNORE to HintIgnore.

In [KDE Solid 6.7.0 StorageAccess](https://github.com/KDE/solid/blob/v6.7.0/src/solid/devices/backends/udisks2/udisksstorageaccess.cpp), teardown unmounts first. Its successful completion path checks CanPowerOff before sending PowerOff; MediaRemovable devices can instead take an Eject path, and encrypted devices have separate teardown handling. HintIgnore is honored by isIgnored. The PowerOff call shown there is NoBlock: the upstream report of an entire desktop hanging is not independently established by this source trace. The actual shipped KDE/UDisks versions remain unverified.

[Linux v6.19 USB sysfs](https://github.com/torvalds/linux/blob/v6.19/drivers/usb/core/sysfs.c) locks and unconfigures the device before calling usb_remove_device; [hub.c](https://github.com/torvalds/linux/blob/v6.19/drivers/usb/core/hub.c) obtains parent-hub runtime PM and requests logical disconnect. These reference paths explain what desktop PowerOff can enter; they do not identify the tablet's exact blocked call or prove a kernel fix. The normal tablet recipe inherits SM8650/7.2.8 and adds its own patches; patch 0012 affects DWC3, Type-C/UCSI, PHY and mux behavior, not those USB-core functions. No kernel source/patch was changed here.

## Integration repairs

1. **Substring board match:** upstream `grep -aq lenovo,tb321fu` also accepts `lenovo,tb321fu-pro` and prefixed names. Both rules now use `grep -azqx` to match a complete NUL-separated compatible entry. The local tablet DT contains exactly `lenovo,tb321fu` followed by `qcom,sm8650`. Missing DT or another board fails the match.
2. **USB SATA enclosure omission:** upstream `ID_BUS==usb` misses USB bridges with ATA identification. [systemd v257 persistent-storage rules](https://github.com/systemd/systemd/blob/v257/rules.d/60-persistent-storage.rules.in) run ata_id for some USB disks; [usb_id](https://github.com/systemd/systemd/blob/v257/src/udev/udev-builtin-usb_id.c) preserves an existing ID_BUS and emits ID_USB properties. Use `SUBSYSTEMS==usb` instead, retaining block/disk and add/change restrictions. This follows the physical USB ancestry used by UDisks rather than relying on its identification bus string.
3. Correct the comment that unmounting alone universally makes removal safe. Preserve normal unmount/error handling and state that all filesystems must be unmounted before unplugging. The workaround only stops advertising desktop power-off support; it does not force an unmount, clear a busy device or guarantee media cache behavior.
