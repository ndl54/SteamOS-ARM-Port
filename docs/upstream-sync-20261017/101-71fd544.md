### Host Bash error diagnostics

Accepted source101's `set -Eeuo pipefail` and ERR trap, which prints line and command to stderr. Inherited ERR handling reaches functions/substitutions/subshells; pipefail remains active. Existing explicit error handlers keep their specific messages, including the remote card command's checked `|| die`. Error text does not enter stdout or binary ADB data. Existing host EXIT cleanup preserves the original failure status, including after successful lock removal.

Bash ERR is diagnostic, not a substitute for explicit status checks: conditional/AND-OR contexts suppress it, explicit exit uses its own status, and abrupt signals/power loss are outside its guarantee. The Android CARD body stays portable `sh` with explicit checks and an EXIT trap, without Bash ERR/errtrace/pipefail requirements.

### Reproduced card hash false-success and repaired it locally

Isolated probes of the pre-repair CARD body reproduced **four false-success cases**: both `sha256sum` calls failing, or both returning empty digests, under each of dash and Bash. The shared `hash()` helper pipes sha256sum to cut without pipefail; the two empty substitutions compared equal, allowing rename/sync/cleanup and exit0. This was a real status-propagation defect, not a test-only missing diagnostic.

Added CARD-local `card_hash()` and `verify_card_copy()`. Check sha256sum status before parsing, validate a 64-character lowercase hexadecimal digest with the existing validator, and check each source/readback assignment before comparison. Nonzero sha256sum with even plausible digest stdout, empty output, readback-only errors and differing hashes now fail before any publication. Changes are local to the reviewed card stage; shared Android storage and Action are byte-identical to starting main.

The portable card EXIT cleanup now captures the original status, reports the active stage (mount/copy/readback/publish/sync), disables its own trap, and explicitly exits with the preserved result. If unmount fails, it retains the owned mount/directory and returns failure without rmdir. Failed rmdir also cannot turn a successful run into success. A prior copy status37 remains37 even when unmount also fails; successful cleanup never erases the original error. The host then emits its checked card-stage error and cannot reach the success message.
